# 无头运行（Agent-Native 支柱 ②）

> `xgame-editor --headless`：**不开窗口**把项目跑 N 帧，向 stdout 输出机器可读的
> JSON 统计 —— 帧耗时分布、实体 / 刚体计数、脚本与组件日志（含 error 样本）、
> 非有限变换检测、音频状态。MCP 的 `run_headless` 工具是它的透传壳。
>
> **为什么**：`--check` 回答"项目能不能加载"，无头运行回答"**跑起来会怎样**"。
> CI 与 AI 智能体的"改完看效果"闭环，缺的就是后一半（见
> [`差距分析.md`](差距分析.md) 文末战略章「近期计划」第 ② 条）。

---

## 用法

```sh
# 跑默认示例项目 300 帧，stdout 出 JSON
cargo run -p xgame-editor -- --headless projects/SampleScene

# 独立产物（dist/）同理
dist/xgame-editor.exe --headless --frames 600 --report report.json projects/SampleScene

# 观察跑完后的世界：场景落盘成 RON（可 diff、可喂回 scene_write）
dist/xgame-editor.exe --headless --frames 300 --dump-scene ended.ron projects/SampleScene
```

| 选项 | 默认 | 说明 |
|---|---|---|
| `--frames N` | 300 | 跑多少帧；1..=100000 |
| `--dt 秒` | 项目 `runtime.fixed_dt` | 每帧推进的秒数；要确定性就沿用默认 |
| `--report 路径` | 无 | 额外把报告写一份到文件（stdout 照常输出同一份） |
| `--dump-scene 路径` | 无 | 把**跑完后**的场景以 RON 落盘 |
| 位置参数 | `projects/SampleScene` | 项目根目录（含 `project.ron`） |

### 退出码契约（与 `--check` 对齐，给 CI / 智能体）

| 码 | 含义 |
|---|---|
| `0` | 干净跑完 |
| `1` | 加载失败或参数错误（项目 / 场景 / 参数读不了，**报告不产出**） |
| `2` | 跑完但观察到问题：脚本 error 日志、非有限变换（**报告照常输出**） |

`2` 的哲学与 `--check` 一致：**"发现问题"与"没跑起来"是两回事** —— 前者报告是
完整可用的，智能体读 `error_samples` 就能定位；后者连观察的机会都没有。

## 报告（字段名即契约）

stdout 是 pretty JSON（示例截断）：

```json
{
  "ok": true,
  "engine_version": "0.1.0",
  "project": "SampleScene", "root": "D:\\...", "scene": "Scenes/scene.ron",
  "scene_name": "Test Scene",
  "frames": 300, "dt": 0.016666668, "fixed_dt": 0.016666668,
  "setup_ms": 1.1, "run_ms": 8.6, "total_time": 4.9999995,
  "entities": 14, "bodies": 10, "colliders": 10, "fixed_steps": 300,
  "non_finite_transforms": 0,
  "frame_us": { "mean": 28.5, "min": 16.5, "max": 1306.7,
                "p50": 26.0, "p95": 38.3, "p99": 61.3 },
  "logs": { "info": 0, "warn": 0, "error": 0 },
  "error_samples": [],
  "audio": { "available": false, "active": 1, "cached_clips": 1, "failed_clips": 0 },
  "scene_dump": null
}
```

- `ok`：`logs.error == 0 && non_finite_transforms == 0`（退出码 2 的判据）。
- `frame_us`：逐帧 `World::update` 的耗时（微秒），百分位用**最近秩** —— 报告里
  每个数都是"真实出现过的一帧"，不是插值出来的假想帧。
- `logs`：脚本与组件日志的计数，含**装载期**（帧 0）脚本编译失败这种一次性日志；
  `error_samples` 最多带 10 条（`脚本: 消息` 形式），计数是全的。
- `audio.available: false` 是无头运行的正常形态（silent 降级：命令、解码、
  缓存、计数照常，只是不出声）——不是错误。
- `scene_dump`：`--dump-scene` 写出的路径（没给是 `null`）。

**改动约束**：字段名与嵌套结构是稳定契约（消费方：CI 断言、MCP `run_headless`）。
新增字段允许（读方按需取），改名 / 删除要同步改
`crates/xgame-editor/src/headless.rs` 的 `json_contract_has_stable_keys` 测试与本文。

## 确定性（刻意的）

每帧推进固定 `dt`（默认 = 项目固定步长）、没有输入、没有墙钟依赖 —— **同一个
项目跑两遍，结果逐位一致**（`falling_ball_is_deterministic_across_runs` 钉死：
两次运行的落盘场景 SHA256 相同）。物理与脚本按同一串时间推进，适合：

- 回归基准：改引擎后跑同一场景，比对 `dump-scene` 的差异；
- 变更验证：改场景 / 脚本前后各跑一次，看报告与落盘场景的 diff。

`--dt` 给非固定步长的值是允许的（时钟每帧补多个固定步），但**要确定性就沿用
默认**。

## 明确不做的事（边界，写给正在用它的智能体）

- **不开窗口 / 不建 GPU / 不开声卡**：CI 与无显卡机器直接能跑。音频走 silent
  引擎，`audio` 节不是零值（解码照常）。
- **不加载资产到 GPU**：模型 / 纹理是渲染器的事；引用完整性由 `--check` /
  MCP `project_check` 管。
- **不推进动画播放时钟**：动画采样在渲染宿主侧（`AnimationDriver`），脚本推的
  `set_anim_param` 等参数照常写入场景，只是没人消费。
- **不重新编译 Rust 插件**：`Plugins/*.dll` 按现状加载（与打包出的游戏同一条
  路径）；改了插件源码要先在编辑器里 Play 一次或重跑 PIE 构建。
- **不做输入模拟**：无头运行没有输入源；靠输入驱动的脚本行为不会被推进。

## 实测（本机样本，2026-10-16；绝对值随机器浮动，看数量级）

| 场景 | 300 帧墙钟 | 其中帧循环 | 帧均值 |
|---|---|---|---|
| `projects/SampleScene`（14 实体 / 10 刚体 / 3 脚本 / 1 音源） | ~80 ms | 8.6 ms | 28.5 µs |
| `projects/BehaviorsDemo`（Rust 插件 + Lua 脚本共存） | ~70 ms | 1.3 ms | 4.4 µs |
| 基线：`--frames 1` / `--check`（进程启动 + 装载） | ~62 ms | — | — |

读法：一次无头调用的**固定成本 ≈ 进程启动 60 ms**（Windows 加载链接的 DLL），
帧循环本身极便宜（300 帧个位数毫秒）—— "跑一下看看"在智能体循环里是廉价操作。

## MCP 对接（`run_headless`）

- **透传**：工具 spawn 与 server **同目录**的 `xgame-editor`（`target/debug/`
  与 `dist/` 都是同目录布局；`cargo test` 时 server 在 `deps/` 下，向上找一级），
  用 `--headless` 跑，把 stdout 的报告原样封进信封：

  ```json
  { "exit_code": 0, "report": { ...上面那份报告... },
    "scene_ron": "（include_scene=true 时才有）" }
  ```

- **为什么是 spawn 而不是把逻辑搬进 MCP crate**：无头运行跑的是 `World::update`
  —— 与编辑器 ▶ Play、独立游戏同一段代码；实现住在编辑器二进制（`--check` 的
  邻居），MCP 只做壳，两处共用一条进化路径。
- **失败分层**：项目打不开（退出码 1）→ 工具 `isError`；跑完但有脚本 error
  （退出码 2）→ **成功返回**，问题在 `report.ok` / `error_samples` 里。
