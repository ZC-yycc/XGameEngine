## 二、脚本层决策索引（D1–D11）

原文与完整论证在 [`双轨语言架构计划.md`](双轨语言架构计划.md)「决策记录」一节，
这里只留一行摘要，防止改脚本层时漏读：

| 决策 | 结论 |
|---|---|
| **D1** | 语言范围收敛为 **Rust + Lua**；C# / Verse / 多语言中立层已否决 —— 维护两套语言边界的成本远超收益 |
| **D2** | Rust 侧走 **UE 插件模式**（cdylib + 注册表），Bevy 式"组件即数据"因跨 DLL 类型信息不可用而否决 |
| **D3** | Lua 侧走 **Unity 模式**（脚本挂实体 + 四个生命周期钩子）+ 热重载 |
| **D4** | Rhai 的去留**由数据决定**：P2.5 三负载基准闸门，不靠直觉 |
| **D5** | 性能结论先量后动：没有探针数据的"优化"不进主干 |
| **D6** | P0 落地注记（门面 / 方法层 / 组件 / 插件边界） |
| **D7** | P0.5 落地注记（编辑器 PIE：后台构建 + 临时副本加载） |
| **D8** | P1 落地注记（`#[derive(Inspect)]` + 编辑器调参） |
| **D9** | P1.5 落地注记（组件参数落盘 + 撤销语义修正） |
| **D10** | P2 落地注记（Lua 宿主 + 路径驻留表） |
| **D11** | P3 落地注记（删 Rhai、收敛单一 Lua 轨） |

**仍然生效的脚本层约束**（P3 之后重述，去掉双轨时期的历史包袱）：

1. **单轨只认 `.lua`** —— `list_scripts` / 加载 / 热重载 / 检查都是这一条；残留
   `.rhai` 不进下拉、也不被 `--check` 误报（`check.rs` 只查文件存在，不查扩展名）。
2. **每脚本环境表的 `__index` 必须挂真元表** —— 往 env 表塞同名普通字段对读取无效，
   表现是"脚本里宿主 API 全变 nil"（P2 首跑 9 条红就是它）。
3. **路径驻留表 id 永不清** —— `invalidate*` 只清编译缓存；清表 = 热重载后每实体
   状态静默错位（`state_survives_hot_reload_even_when_intern_order_changes` 钉死）。
4. **沙箱预算 200_000 条指令**（Lua 指令钩子，每 1024 条查一次）；改预算要有
   性能/安全两侧的数据，别单方面放宽。
5. **API 名一字不改** —— `spawn_entity` 的 `_entity` 后缀是 Rhai 保留字时期的历史
   产物，迁移成本大于违和感；改名等于作废所有已写脚本。
6. **`host.rs` 不改名不搬家** —— `lua_host.rs` 的 `use crate::host::` 与再导出路径
   全不动，保持纯删代码的最小 diff。
7. **`ScriptCtx` 是地址束** —— unsafe 有严格调用窗口约定（见 `context.rs` 模块文档），
   窗口外解引用是 UB；改它之前先读那段文档。
8. **`GameCtx` 方法层是 API 真相源** —— `ctx.rs` 写实现，`lua_api.rs` 只是每函数
   一行的转发壳；新增 API 两处都要动，但逻辑只准写在 `ctx.rs`。

## 三、脚本宿主的实现事实（省得重新踩）

- **路径借用跨不过 `&mut self`**：借 `self.intern` 的 `&str` 调 `&mut self` 方法会被
  借用检查器拒绝（它看不出这是字段级拆借）—— `ensure_loaded` 因此拆成 path 外壳 +
  `ensure_loaded_id` 内核、`run_hook` 收 `path_id`，路径解析都在方法体内做。
- **钩子句柄编译期缓存**（`detect_funcs` 留 `Option<Function>`）省每钩子 `env.get`
  ~194 ns；**ctx 常驻槽 + 轻量指针传参**（`ctx_slot: Box<MaybeUninit<LuaCtx>>`）省每
  钩子现造 userdata ~284 ns。两处合计把 Lua 轨分发从 1670 压到 576 µs/帧（-65%）。
- **基准工具必须断言"脚本真跑了"**：宿主对编译失败只记日志是产品正确语义，但基准
  必须自己 panic —— 否则"空调度"会被当成假快（P2.5 首跑就栽在这）。

## 四、Rust 组件与插件（P0–P1.5）

**三条不能推翻的约束（D7）**：

1. **`Plugins/` 是唯一规范目录** —— 玩家与打包器只认这里，编辑器构建产物同步进来。
2. **加载永远走临时副本** —— Windows 文件锁会让 `cargo build` 覆盖不了正在加载的
   DLL；临时副本是唯一稳的做法。
3. **旧 DLL 句柄永不卸载** —— 悬垂 vtable 是 UB（进程暴毙无 panic）。持有句柄的
   字段必须声明在 `game_runtime` / `world` **之后**（析构顺序）。

**四条不能推翻的约束（D8，其中第 ④ 条已被 P1.5 推翻）**：

1. **组件契约是 `Behavior: Lifecycle + Inspect`**（不是 `Lifecycle`）—— 编辑器不链接
   用户代码，拿 `&mut dyn Inspect` 只能靠实例自带的字段表；存 `Box<dyn Lifecycle>`
   时这条降级做不到（需 downcast，跨 DLL 无共享类型信息）。
2. **`Inspect` 是"表 + 下标"，别改成闭包** —— 跨边界闭包要处理 panic 隔离与函数
   指针生命周期，表 + 下标是唯一稳的形态。
3. **寻址名永远是 Rust 字段名**，`label` 只改显示名 —— 重命名显示名不能破坏脚本。
4. ~~组件字段改动不进场景撤销栈~~ → **已推翻**：参数进场景文件后已成为场景数据，
   不进栈会凭空丢一条编辑。现为拖拽挂 `undo_pending`、松手入栈、离散编辑当场 push，
   与 Name/Transform 同通道。**Play 中热调参仍不写回**（停止靠场景快照还原）。

**两条不能推翻的约束（D9）**：

1. 参数表的键是**注册名**而非 `behaviors` 数组下标 —— 下标会错位，参数是持久化数据，
   错位写参表现为"改 A 组件的参数写进 B 组件"，两边都是 `f32` 时无从发现。
2. `FieldKind` / `FieldValue` 的 serde **变体标签即磁盘格式**
   （`field_value_ron_variant_labels_are_stable` 钉死）；改标签名 = 作废所有旧场景。

**两条实现事实**：

- `PluginSession` 留的常驻注册表是每帧路径（查字段表 / 构造编辑态副本）的唯一通道，
  **别改回 `build_registry()`** —— 后者每次重跑插件入口且失败时 `log::error!`，错位时
  会变成每帧一条错误日志。
- **插件注册表是跨编译单元的内存布局**：给 `BehaviorEntry` 加字段 = 改 ABI，会让过期
  的 `target/*.dll` 变成 `0xc0000005`。而 `cargo test` 不产出 cdylib，那些 DLL 极易
  过期 —— `plugin_loading` 因此在取 DLL 前先嵌套构建一次（MCP 测试同理）。

## 五、音频（第八阶段）

**四条不能推翻的约束**：

1. **脚本层不引 kira** —— 脚本音频 API 只往 `AudioPort` 塞命令，`World` 帧末统一
   结算（`GameCtx.audio: Option<&mut AudioPort>`，None 静默 no-op）。设备失败走
   **silent 降级**（照常受理 / 计数 / GC，只是不出声），别改成"没设备就报错"。
2. **监听者与主音量是 port 上的状态字段，不进命令束** —— 姿态每帧被覆盖，混进
   "发生过的事"会变成回放一串状态更新的荒诞语义。
3. **`PlaySound.follow` 是实体绑定、不是空间化开关** —— 空间化只看
   `position.is_some()`；非空间化声音**也要绑实体**（否则"删实体音还在响"，
   `removed_entity_or_component_stops_its_sound` 钉死）。
4. **音频每渲染帧同步一次、不跟物理固定步同频** —— 人耳对 16 ms 的位置更新不敏感，
   固定步一帧可能跑多个。

**两条实现事实**：silent 模式用**墙钟** GC、设备模式看 `handle.state()==Stopped`；
测试要断言"声音在响"必须用 ≥1 秒的 WAV（50 ms 的会被 GC 先真掉，曾造成假红）。
kira 的 glam 0.33 与引擎 glam 0.29 **类型不出 `xgame-audio` 墙** —— 跨界只传
`[f32;3]` / `[f32;4]` 数组。

**热路径快速路径**：`sync_audio` 的实体表扫描在无音频场景实测 +5.7 µs/帧
（2000 实体纯视觉），故加 `audio_sources_seen` / `audio_scan_count` 守卫 ——
没挂过音频源、无 autoplay、实体数不变 ⇒ 整段跳过；实体数变化重新武装扫描。
**刻意取舍**：运行中给已有实体直接贴 `audio` 组件（不动实体数）不触发重扫 ——
动态发声正路是脚本 `play_sound`（不经扫描）。

## 六、Agent-Native（无头运行 / MCP）

**三条不能推翻的约束**：

1. **无头运行的实现住在编辑器二进制**（`headless.rs`，`--check` 的邻居），**不做第二份
   帧循环**（单一运行时铁律；MCP 只 spawn 透传）。
2. **退出码 `2`（跑完有问题）不是工具失败** —— 报告照常产出，`isError` 只留给
   "打不开项目"。
3. **报告 JSON 字段名是稳定契约** —— `json_contract_has_stable_keys` 钉死，消费方 =
   CI + MCP；新增字段可以，改名 / 删除不行。

**两条实现事实**：MCP 测试 spawn 编辑器**前必须嵌套 `cargo build -p xgame-editor`**
（`cargo test` 不产出常规 exe；过期编辑器不认 `--headless` 会弹窗挂死测试）；
`find_editor_exe` 找同目录 + **上一级**（`cargo test` 时 server 在 `deps/` 下跑）。

**实测**：SampleScene 300 帧墙钟 ~80 ms（帧循环 8.6 ms、帧均值 28.5 µs）；
BehaviorsDemo（插件 + Lua）~70 ms；进程启动固定成本 ~60 ms（与 `--check` 同量级）。

## 七、PBR 与材质（2026-10-19）

**四条不能推翻的约束**：

1. **灯亮度按 `radiance = intensity × π` 标定** —— 别"顺手修正"成物理严格的 intensity，
   全部旧场景会暗 3.14 倍。
2. **材质参数是逐 draw 的**（`DrawUniform` 112 B + 动态偏移）—— 别改回"每材质一个
   绑定组"（逐实体覆盖下按资产缓存要么重建绑定组、要么缓存键随数值膨胀）。
3. **`scene_signature` 必须哈希 material** —— 漏了 = 暂停时调色视口不刷新。
4. **默认截图机位必须顺光** —— 相机方位 = 主方向光 XZ 方位角 + 35°、仰角 26°；
   背光机位会把 PBR 画面拍成"渲染坏了"。

**三条实现事实**：`MIN_ROUGHNESS = 0.04`（GGX 在 roughness=0 时除零 → NaN 扩散整帧）；
`--screenshot` 是**唯一**推进动画时钟的无头路径（静态截图里角色不能停在绑定姿态）；
像素断言必须算一遍镜面项（光与相机同轴时 GGX 副瓣会在中心像素叠 ~0.24 线性白）。

**已知限制**：脚本侧没有 `set_material`（入口 = Inspector / 场景 RON / MCP
`scene_write`）；天空关着时环境反射仍是常量近似。

## 八、HDR + ACES + Bloom（2026-10-19）

**四条不能推翻的约束**：

1. **亮度基线不许动**（π 标定 + 曲线前 `/0.6`；动它 = 全部旧场景明暗整体挪档）。
2. **Bloom 阈值在曝光后判**（threshold = 1.0 ≈ 显示白点）—— 挪到曝光前会让"调曝光"
   与"调阈值"耦合。
3. **光晕加在曲线前** —— 曲线后加是贴纸：暗部蒙灰、高阈值时光晕先在 LDR 端被裁出
   硬边。
4. **Bloom 默认关**（`intensity == 0` 是唯一关闭形态），关着时**整段跳过**（不建纹理、
   不记录 pass、链丢 None）—— 别改成"跑一遍乘 0"。

**三条实现事实**：每级必须 a/b 纹理乒乓（同一张纹理不能既当输入又当输出，wgpu 提交时
校验）；合成绑定组键 =（源代, 尺寸, 开关），关着时 mip 槽位用源视图占位、着色器按
uniform 值分支；报告 / MCP JSON 里 f32 是精确加宽的 f64（`0.6` → `0.6000000238418579`），
消费方按 f32 精度比较。

## 九、程序化天空 + IBL（2026-10-19）

**四条不能推翻的约束**：

1. **默认关**（`enabled = false`）—— 关着时 uniform 照写（开关位 0）但**不重建任何
   资源、不采样三张环境纹理**，画面与天空上线前逐位一致；别改成"默认开"或"关也重建"。
2. **环境立方体 / LUT 固定分配、内容按 key 重建**（key = SkyUniform 字节 FNV 哈希）——
   绑定组对象身份必须稳定（换对象 = 每帧路径重绑），别改成"每帧重建"。
3. **加载恒等：太阳 = 场景 `packed`（active、≤8 盏）里第一盏方向光**（方向取传播方向
   的反向、颜色取灯色）；没方向光就没有太阳（强度写 0）。别引入第二套"天空光源"。
4. **IBL 与常量 `ambient` 相加**（SH 存 E/π 就是为这条标定 —— 均匀环境下两者逐值
   等价），别把 ambient 顶掉。

**三条实现事实**：`SKY_COMMON_WGSL`（`sky_radiance` / `sky_sh_eval`）**不声明绑定**，
三处（天空盒 FS / 场景 FS / 预过滤 FS）各自声明自己的绑定号（全局组 7–11 的契约集中在
`sky.rs` 的 `global_layout_entries()`）；场景 FS 用 `sky.sun_dir.w > 0.5` 判开关
（uniform 常量 ⇒ 采样在整个 draw 里控制流一致）；预过滤面基向量由 CPU 给
（`cpu::cube_face_basis`，`dir = forward + right·(2u-1) + up·(1-2v)` 对齐 WebGPU
立方体约定，错位表现 = "反射里太阳跑到反侧"，GPU 测试钉住）。

**性能实测**（RTX 2060 / 1280×720 / MSAA×4，`postfx_cost.rs` 的 `sky_ibl_cost`）：
稳态开相对关 **+29.5 µs/帧**；每帧重建（太阳每帧动的最坏情况）**+341.7 µs GPU /
+449 µs CPU**；开启那帧一次性成本 = 重建 + 71.6 µs（BRDF LUT + 冷态）。

## 十、GPU 实例化（2026-10-19）

**四条不能推翻的约束**：

1. **批次分组键 = 图元地址**（只做相等判定）、**批次顺序 = 首次遇到顺序** —— 无头截图 /
   基准"同机逐字节确定"契约依赖槽位布局确定，别改成哈希序 / 按材质排序。
2. **逐实例数据一律走 `draw_buffer`**（storage 整缓冲一次绑定）—— 别退回"逐 draw 动态
   偏移 uniform"，那是 2000 实体场景 ~1.9 ms/帧 的 CPU 税（本轮实测）。
3. **半透明不参与合批**（排序语义优先）。
4. **材质绑定组在收集阶段预热**（绘制循环只有 `&self`、不能惰性建组）—— 循环里的
   `material_cache.get(..).expect()` 是故意的硬失败（静默用错材质 = 画错色）。

**实测**（同机交替 3 轮取中位数，RTX 2060 / 1280×720 / MSAA×4 / 2000 实体，
`instancing_cost`）：共享网格 2001 批 → **2 批**、CPU **2225 → 344 µs/帧（-84%）**；
各自网格对照档 4139 → 3287 µs/帧（-21%）。端到端钉子：同一 SampleScene 无头截图
（150 帧 + `--screenshot`）在两版之间**逐字节一致**。

## 十一、视锥剔除 + 阴影补投（2026-10-20）

**四条不能推翻的约束**：

1. **保守性是硬合同** —— 开/关剔除逐位一致（`frustum_culling_matches_unculled_pixels`
   钉死）；矩阵退化（含 NaN / 零法线）必须返回 `None` 并**当作不剔除**，宁可白画不能
   黑屏。
2. **相机外投影物必须保留在阴影视锥里**（`offscreen_casters_still_cast_shadows` 钉死）——
   只按相机视锥剔会让影子凭空消失。
3. **蒙皮包围盒是绑定姿态，50% 余量不能删**（`cull_bounds_pads_skinned_meshes_only`
   钉死）；静态网格不得加余量。
4. **剔除不改变分组键 / 批次顺序**，只少实例或整批不出现 —— 槽位布局确定性的前提。

**三条实现事实**：收集顺序是**主 pass 不透明 → 半透明 → 仅阴影**三段连续槽位，仍只做
一次 `queue.write_buffer`；`FrameStats.opaque_instances` **只算主 pass**，仅阴影实例单独
记 `shadow_only_instances`，`cull_ratio()` 的分母两者都算；`Bounds::transformed_affine`
是 8 角点法的解析等价式（每帧省 7 次点变换，交叉单测钉住）。

**实测**（RTX 2060 / 1280×720 / MSAA×4 / 2000 实体 / 30° 窄视场 / 56.6% 剔除，
`culling_cost`）：未合批场景 **2000 → 868 批、CPU 3295 → 1146 µs/帧（-65%）、
场景段 158.0 → 108.5 µs（-31%）**；共享网格场景 CPU -3% / 场景段 -7%。
阴影刻意关（相机外投影物按设计保留，混进来测的是组合而不是剔除本身）。

## 十二、FXAA（2026-10-20）

**四条不能推翻的约束**：

1. **默认关，关着时整段跳过** —— 不建 scratch、不做 pass、不写 uniform，画面与上线前
   逐位一致（与 Bloom 同一条纪律）。
2. **luma 与混合必须在显示空间** —— sRGB 目标采样是线性值，着色器先 `srgb_encode`、
   混合后 `srgb_decode` 交还硬件；非 sRGB 目标（合成已手动编码）原样处理。
3. **边缘检测的采样必须用 `textureSampleLevel(..., 0.0)`** —— 分支建立在采样值上，
   WGSL 不允许隐式 LOD 采样出现在非一致控制流。
4. **平坦区域必须回原采样值**（范围低于阈值且亚像素项为 0 时），不做 encode/decode
   往返 —— 8 位量化边界上会悄悄差 1 LSB。

**两条实现事实**：scratch 的格式 = 输出格式、尺寸跟源走，尺寸变化整块重建并重建
绑定组；FXAA 测试**强制 1× MSAA**（4× 的硬件斜边会掩盖效果），旧实现下开 / 关两张图
逐字节相同就是它的先证红。

**实测**（RTX 2060 / 1280×720 / MSAA×4，`postfx_cost` 第四档）：HDR+ACES 后处理
24.7 µs/帧 → 开 FXAA **72.2 µs/帧（端到端 +47.6 µs，+30.6%）**；1× MSAA 测试场景
硬台阶 672 → 374（**-44%**）、中间调像素 0 → 804、平坦背景角点逐字节不变。

**阈值口径**：亚像素 0.75 / 方向收缩 1/8（下界 1/128）/ 跨度 8 texel 都是 3.11 原值；
边缘阈值取 1/12 与 1/6（stock 是 1/24 与 1/8）—— 默认已有 MSAA，stock 阈值会整幅柔化。

## 十三、性能纪律与工具链

**方法与数据**（微基准 `behavior_dispatch_throughput`，1000 no-op 实体 × 300 帧，
P2.5 会话）：Lua 轨分发 **562 µs/帧**、Rust 组件轨 71.7 µs、无轨基线 7.54 µs。
历史：P0 = 493.9、P0.5 = 68.4、P1 = 65.2、P2 = 713 µs。

**三条纪律**：

1. **先量后改**：没有探针数据的性能改动不进主干；改动前后同机背靠背，最好交替 3 轮
   取中位数。
2. **基准必须断言"真的发生了"**：脚本没跑、pass 没执行时，"更快"是假的（P2.5 与
   FXAA 基准都栽过，各自加了守卫）。
3. **绝对值随机器状态浮动 1.5× 以上**：跨版本比较必须同机背靠背；组件轨 < 50 µs 的
   验收线在本机持续红（P0.5 起已知，**不为了迁就机器上调验收线** —— 红了先对同机
   数字再判回归）。

**工具链注意**：仓库源文件是 UTF-8 **无 BOM** 且含大量中文注释。用 PowerShell 做
文本替换必须显式 `-Encoding UTF8` 读写，否则 PS 5.1 会按 GBK 解码把中文**有损**毁掉
（已发生过一次，PLAN.md 十六第七节）。改中文源文件优先用编辑器工具，shell 只做只读。

## 十四、资产管线：GUID + `.meta`（2026-10-20）

**要改的东西**：场景 / 预制体里的资产引用、资产导入、资源浏览器、
`ProjectHandle::load_*` / `write_*`、`--check` 的诊断项。

### 1. 磁盘存 GUID，内存存路径

这是本层最重要的一条，别推翻：

- **磁盘**（场景 / 预制体 RON）：`model: "guid://8f3a…"`。
  资产改名 / 挪目录只改 `.meta` 的位置，引用不断链。
- **内存**（`Entity::model` / `AudioSource::clip` / `scripts` / `PrefabInstanceRef::source`）：
  仍然是**项目相对路径**。渲染、物理、音频、脚本、UI 全部按路径打开文件，
  它们不需要知道 GUID 的存在。

转换点只有一处：`ProjectHandle::load_scene` / `write_scene` / `load_prefab` /
`write_prefab`（`xgame_core::asset` 的 `encode_*` / `decode_*`）。

**为什么不做成"字段类型换成 AssetRef"**：那要把 243 个消费点全部改写，
还会把"GUID → 路径"的解析塞进每帧热路径；而边界转换是同一个语义、零热路径成本。
代价是资产被删后内存里会残留 `guid://…` 字符串 —— 这恰好是想要的：
`--check` 能把它点名（`dangling_guids`），而不是静默当成空引用。

### 2. `.meta` 的规则

- 每个被登记的资产生成一份 `<文件名>.meta`（RON）：`guid` + `kind` + `import`。
- **GUID 只在首次导入时生成一次，之后永不变**（改名 / 移动都不变）。
- 场景不登记资产（它由 `entry_scene` 按路径引用，没有"改名不断链"需求）；
  `project.ron` 不是资产。
- 构建产物目录（`target/` `dist/` `Plugins/` 等）不扫（`SKIPPED_DIRS`）。
- 资产类型按扩展名白名单推断（模型 / 纹理 / 音频 / 脚本 / 预制体 / 着色器），
  未知扩展名不进库 —— 否则 `src/*.rs`、`Cargo.toml` 都想成为资产。

### 3. `--check` 必须只读

`scan` 只读盘、只报告；**生成 `.meta` 是显式动作**（`ensure_metas`）。
`--check` / MCP `project_check` / `asset_list` 都不调用它 —— 检查一遍不能改变项目，
否则 CI 与智能体的"改 → 查 → 验"闭环会在工作区里留下意外的文件。

### 4. 迁移是隐式的，且不许吃掉注释

- 老项目：`--migrate-assets <项目>` 一次性生成 `.meta` 并把引用改写成 GUID。
- 迁移用**字符串字面量替换**（`"Resources/Box.glb"` → `"guid://…"`），
  不是"读出来整体重新序列化"：本仓库的示例场景是**带注释的文档**，
  整份重写会把注释全部吃掉（第一次实现就踩了，`git diff` 才看出来）。
- 打开旧项目 + 保存一次也会完成迁移（`write_scene` 自动编码）。

### 5. GUID 冲突 = 必须修的错误

两台机器 / 两次手工拷贝可能让两个资产共用一份 `.meta` 内容。冲突时解析结果
取决于扫描顺序（= 随机），所以扫描按路径字典序**取第一个**保证确定性，
同时把冲突列进 `diagnostics.conflicts`，`--check` 与 `asset_list` 都会报。

### 6. 导入设置目前只落盘，渲染尚未消费

`ImportSettings`（`model_scale` / `texture_srgb` / `texture_nearest` /
`audio_streaming`）已经写进 `.meta`、编辑器能改、重开项目仍在；
但**渲染侧还没读它**：

- `model_scale` 的正确实现是烘焙进网格（顶点 + 骨骼节点 + 逆绑定矩阵 + 动画
  translation 轨道都要一起缩放）或在世界矩阵外再乘一层；前者工程量不小，
  后者会与物理碰撞不一致。半吊子接线比不接线更糟，故留到下一刀。
- `texture_*` 眼下没有消费点：材质还没有纹理槽位（`MaterialOverride` 只有 PBR 参数），
  独立纹理资产还没有被任何东西引用。

### 7. 场景里的注释要保住

编辑器保存（`write_scene`）是全量序列化，会吃掉注释 —— 这是本功能之前就有的
行为，不是这轮引入的。所以**教程性质的示例场景不要用编辑器反复保存**；
需要保注释的批处理（迁移）走字符串替换那条路。

## 十五、角色控制器：封装 rapier + 四道绕过（2026-10-20）

**要改的东西**：`xgame-core::CharacterController` / `Entity::controller`、
`xgame-physics`（`character.rs` + `move_character`）、`xgame-script` 的 `character_*`
与碰撞钩子、`xgame-runtime` 的角色刚体与事件派发、Inspector 的 Character 区块。

### 1. 用 rapier 内置控制器，不自己写扫掠

"沿墙滑行、上台阶、坡度限制、贴地吸附、陡坡滑落"每一项手写都是坑。rapier 的
`KinematicCharacterController` 是上游多年验证过的实现，封装它是"参考开源引擎"最
省事的一条路。**但 rapier 0.22 的这条链路对胶囊角色有四处硬缺陷**（全部实测确认，
不是猜的），所以每一处都在**我们这层**绕过，并且把"为什么"写进了
`crates/xgame-physics/src/character.rs` 的模块文档。

### 2. 四处上游缺陷（改动前必读）

1. **grounded 恒为 false**：`detect_grounded_status_and_apply_friction` 用
   `(Capsule, Cuboid)` 的 contact manifold，而 parry 0.17.6 把这个组合**注释掉了**
   → 返回 `Unsupported`，rapier 用 `let _ =` 吞掉。→ 我们用自己的向下射线判
   grounded（法线点乘 ≥ 1e-3 且法向间隙 ≤ `predict_ground`）。
2. **`check_and_fix_penetrations()` 是空函数**（整段被 `/* */` 注释）。→ 一旦脚底
   与地面重叠，`cast_shape(stop_at_penetration: false)` 对手 "继续深入" 的扫掠返回
   `None`，整段位移被放行；实测从 2.6mm 重叠起步，两帧内退化成每帧沉 0.83m。
   → 移动前做**皮肤层硬约束**（间隙 < `skin_width` 就把向下的期望抬回
   `rest_gap`），并且静止间隙必须是 `skin_width × 1.1` 而不是 `skin_width` 本身。
3. **60° 薄板上胶囊扫掠返回 `None`**（0°/30° 正常，60° 退化；射线探测却正常）。
   → 陡坡滑落自实现：着地且法线超过 `slope_limit` 时，把向下的期望**投影到坡面**，
   切向天然带水平分量，间隙保持不变。
4. **autostep 对胶囊不可用**：`handle_stairs` 只在"第一次扫掠撞到墙"时触发（走路带
   向下期望时第一次撞的永远是地面），且 `min_width`（0.25×半径）不足以把胶囊的
   底面接触点推上台阶，算出的台阶高度恒为 0。→ 关掉 rapier 的 autostep，自己实现
   "抬到台阶高度 → 水平前进（多推一个半径）→ 向下贴回"，三次试探复用 `move_shape`。

**为什么不对 parry 打补丁**：0.17.x 最后一个发布版就是 0.17.6；0.18+ 要求
rapier ≥ 0.23（破坏性升级）。`[patch]` 一个 fork 会把"依赖升级"变成"维护 fork"。

### 3. 坐标约定：实体原点是脚底

`Entity::transform.position` = 角色**脚底**（Unity 同款），胶囊中心 = 原点 +
`center_height()`（`half_height + radius`）。理由：编辑器里把角色拖到 y=0 就是站在
地平面上；场景文件里的高度就是玩家看到的脚底位置。改这条会同时影响
`sync_bodies` 的建体偏移与 `move_character` 的写回，两处必须一起改。

### 4. 碰撞事件：两条来源，一个出口

- **动态刚体**：rapier 的 `CollisionEvent`（`World::step` 里收集，运行时 `drain`）。
- **角色**：运动学胶囊永远停在 `skin_width` 外，和墙 / 地板**从没真正接触过**，
  物理引擎一个事件都不会发（运动学 vs 静态本来也不生成）。所以角色的接触面由
  `CharacterMoveResult::contacts` 上报（`move_shape` 回调里的碰撞体句柄 → 刚体 id，
  固定容量 8、零分配），运行时与上一帧做差分得到 enter / exit。

两条来源都汇到 `World::dispatch_collision_to`，所以脚本与组件看到的语义完全一致：
**双方各收一次**、持续接触不刷屏、`other` 是对方实体 id。差分按
`(小 id, 大 id, started)` 去重，避免两个角色互撞时收到两条反向事件。

### 5. 运行时层：贴地速度必须是 0

`character_simple_move` 着地时**不再**给一个向下的"贴地速度"。带向下分量时
`move_shape` 的第一次扫掠先撞地面，剩余位移被吃掉，自动上台阶永远不触发（0.2m
台阶把角色焊死在原地）。贴地交给 snap（走下矮台阶）与坡面切向投影（走坡）。
下落时的竖直速度用 `effective_translation.y / dt` 反推，着地后按坡面跟随率
`-(n.x·vx + n.z·vz)/n.y` 重算并 `.min(0)` —— 只下不上，上坡的爬升交给物理层的切向投影。
