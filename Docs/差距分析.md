# XGameEngine 差距分析（2026-10-20）

> 对照 Unity / Godot / Unreal / Bevy 的功能面。依据不是印象 —— 是对本仓库 **13 个 crate**
> 的实际盘点（grep 粒子 / LOD / NavMesh / watcher / CI / GUID 全部为空，逐条核对
> `ROADMAP.md` 与 `PLAN.md` 的落地记录）。
>
> **这份文档是优先级与能力矩阵的唯一真相源**：`ROADMAP.md` 只记阶段状态，`PLAN.md`
> 只记"当时为什么这么做"，评测与排序都在这里。上次全量盘点 2026-10-12，本轮
> 2026-10-20 按 FXAA / 剔除 / 实例化 / IBL 落地后的代码重新核过一遍。

**统计（2026-10-20）**

| | |
|---|---|
| **2** | **P0** 硬缺口（都是资产管线：GUID / 导入与资源浏览器） |
| **13** | **P1** 重要缺口（做出完整 demo 与产品化所需） |
| **18** | **P2** 规模化 / 产品化第二波 |
| **6** | **P3** 长期（网络、多窗口、地形等） |
| **11** | 已对齐 / 做对（能力矩阵里的 ✅ 行；另有 Agent-Native 的 7 项基础设施单列） |
| **458** | 回归测试（另 6 条性能基准默认 `#[ignore]`），2026-10-20 全量绿 |

**总评**：基础设施层（运行时 / 帧调度 / 性能纪律 / 帧内确定性）已经达到甚至超过不少
开源引擎的水准 —— 渲染的"落后一代"在 2026-10 这一轮基本收口（PBR + HDR/ACES +
Bloom + 天空 IBL + 实例化 + 剔除 + FXAA）。真正的差距只剩三处：
**游戏内容层**（游戏 UI / 粒子 / 角色控制器 / morph，动画与音频主链已齐）、
**资产管线**（按路径引用、无导入管线、Resources 不能浏览 —— 项目一大就是数据债）与
**编辑器产品化**（Profiler / Preferences / 布局持久化 / 多场景）。

一句话排序：**先还资产债，再补"能做出完整 demo"的三件套（角色控制器、游戏 UI、
粒子），渲染只差 TAA 与 CSM 两刀，规模问题（LOD / ECS）等实体数真的上来再动。**
CI 是半小时的零风险收益，应该立刻做，不占优先级档位。

## 一、优先级总表（排序即理由）

### P0 —— 不做会欠债，越晚改越贵

| # | 事项 | 现状 | 为什么是 P0 |
|---|---|---|---|
| 1 | **资产 GUID + `.meta` 等价物** | 全部按项目相对路径引用（`AssetId` 是路径字符串的 newtype，`crates/xgame-core/src/asset.rs`）；重命名 / 移动资产即断链，只能靠 `--check` 事后发现 | 引用格式是**数据格式**：等场景 / 预制体多起来再改，等于重写全部场景文件与所有外部工具（MCP / 脚本 / 编辑器面板）。这是唯一"今天不做、明天更贵"的债 |
| 2 | **导入管线 + 资源浏览器** | 只有 Prefabs 面板（列资产 / 搜索 / 实例化 / 删除）；`Resources/` 里的模型、纹理、音频**不能浏览、不能拖入场景**，也没有导入设置（缩放 / 压缩 / 采样） | 与 1 是同一件事的两端：GUID 解决"引用谁"，导入解决"怎么进项目"。没有它，每加一个资产都要手改 RON —— 这正是智能体时代最不该保留的人工步骤 |

> P0 的完成判据（建议）：场景里引用资产的字段全部改存 GUID；旧路径引用可读入并
> 在保存时迁移；`--check` 能报"GUID 存在但资产缺失"与"资产没有 .meta"；资源浏览器
> 能浏览 `Resources/` 并把模型拖进场景。

### P1 —— 做出完整 demo 与产品化

| # | 事项 | 现状 | 为什么在这个位置 |
|---|---|---|---|
| 3 | **角色控制器 + 碰撞 / 触发事件进脚本** | 有带过滤的射线；无胶囊移动 / 台阶 / 坡度。物理侧能产生 `CollisionEvent`（`PhysicsWorld::drain_events`），但**运行时从未消费**，脚本更拿不到（只有 `raycast`） | 3D 游戏的主角移动与"踩到触发器"是玩法闭环。射线已经有了，move-and-slide 是在它上面的薄层；事件只差把 `drain_events` 接进 `World` 并翻译成脚本调用 |
| 4 | **游戏 UI** | 缺失。egui 是编辑器即时模式 UI，不适合游戏界面（无锚点 / 九宫格 / 动画 / 手柄导航） | 任何可玩的 demo 都需要 HUD、菜单、血条。它是"内容层三件套"里最硬的一件，也是唯一完全没有技术底子的（另两件至少有物理 / 渲染底座） |
| 5 | **材质资产（`.mat`）** | 只有逐实体 `MaterialOverride`（base_color / metallic / roughness）；无独立材质文件、无纹理槽位引用、脚本侧无 `set_material` | 现在"同一个材质"靠复制字段值，改一处要改 N 个实体。材质资产是内容复用的最小单位，也是 P0 导入管线的第一个消费者 |
| 6 | **粒子 / VFX** | 全库无 particle / sprite 代码 | 内容层观感的最低成本项：一个 CPU 粒子系统 + 少量内置发射器就能让场景"活"，GLTF 资产不背这个锅 |
| 7 | **编辑器内 Profiler 面板** | 缺失。命令行 `frame_probe`（`XGAME_FRAME_LOG=<path>`）已有完整数据面 | 数据已经在采，缺的只是 UI。性能问题的第一现场在编辑器，让作者为了看帧耗时去开环境变量是不合理的 |
| 8 | **Preferences + 面板布局持久化** | 缺失。唯一落盘的是最近项目列表（`%APPDATA%\XGameEngine\recent_projects.ron`）；主题 / 相机速度 / 网格 / 吸附默认值硬编码；`egui_tiles` 布局每次启动重建默认树 | 编辑器产品化的"第二波"：每天用的人第一个抱怨的就是"布局又没了" |
| 9 | **多场景管理 + 构建设置** | 只认清单里的入口场景（Save As 可存新文件并切过去）；构建 = 复制播放器 + 全部资产，无场景清单 / 平台配置 / 图标版本号 | 项目一大，"一张大地图"会先撑不住；发布也需要场景清单与元数据 |
| 10 | **TAA** | 未做。FXAA 已落地（默认关） | 渲染侧最后一刀观感：FXAA 只能抹平当前帧的台阶，TAA 用历史帧换更干净的边缘与更低的采样成本；代价是历史缓冲 / 运动向量 / 重投影，属于"要单独当一件事做"的量级 |
| 11 | **级联阴影（CSM）** | 单盏方向光阴影、单级正交视锥按场景包围盒拟合 + 3×3 PCF | 大场景的阴影精度问题在"摄像机拉远"时立刻暴露；CSM 是开放世界的标配，但与 TAA 一样是独立一刀 |
| 12 | **动画 morph target + 分层状态机（Phase B）** | 蒙皮 / 单剪辑 / 交叉淡入 / 阈值状态机 / 叠加 / 多层混合栈 + 骨骼遮罩已落地 | 表情与面部是"角色像人"的最后一公里；不做的话角色只能靠骨骼演。优先级低于玩法闭环 |
| 13 | **脚本 API 补面** | 91 个注册名，覆盖变换 / 实体 / 物理 / 输入 / 时间 / 音频 / 动画参数与层权重 / 日志；缺相机、材质、动画剪辑切换（`crossfade` 只有编辑器 / RON 能触发）、UI、碰撞事件、时间缩放、场景切换、预制体实例化 | 每个缺口都是"必须在引擎里改一行 Rust 才能做"的墙。补面成本低，但应跟着上面各项功能走（UI 有了才有 UI API） |
| 14 | **自动保存 / 崩溃恢复** | 缺失。崩溃即丢全部未保存工作（`Ctrl+S` 是唯一防线） | 归在 P1 末尾：不是能力差距，是"用户会真的丢东西"的风险，成本不高 |
| 15 | **手柄 / 触摸输入** | 键鼠完整（`InputMap` 多绑定 / 修饰键 / 双向轴）；无手柄 / 触摸 | 动作游戏与主机手感的基础；当前所有 demo 都能用键鼠，故排在 P1 末 |

## 七、推荐顺序（未来 10 刀）

排序不只按"重要"，也按**依赖**与**改动代价**：

1. **CI（0.5 天）** —— GitHub Actions 跑 `check` / `clippy` / `test` + `--check` / `--headless`。
   零架构改动，先把 458 条测试从"靠自觉"变成"靠机器"。GPU 断言在没有适配器的 runner 上
   会自动 skip（`gpu_or_skip`），`--screenshot` 留给带 GPU 的自托管 runner
   （或先只跑非截图部分）。不占优先级档位，应该本周做。
2. **资产 GUID + 导入管线 + 资源浏览器（1–2 周）** —— P0 数据债，且越晚越贵。
   建议一刀切成三小步：① `AssetId` 换 GUID + `.meta` 生成与迁移；② 导入设置
   （模型缩放 / 纹理采样）；③ 资源浏览器 + 拖拽入场景。每一步都能独立回归。
3. **角色控制器 + 碰撞事件进脚本（3–5 天）** —— 玩法闭环的第一块。射线已就绪，
   缺的是 move-and-slide 与事件翻译；做完之后"能走能跳能踩触发器"。
4. **游戏 UI 最小集（1–2 周）** —— Canvas + 锚点 + 文本 / 图片 / 按钮 + 脚本 API。
   不要做可视化编辑器，先把运行时与布局做对（egui 的布局思路不能复用）。
5. **材质资产 + `set_material`（3–5 天）** —— 依附于第 2 步的导入管线，内容复用
   立刻上一个台阶；同时把脚本 API 从"改颜色"升级到"换材质"。
6. **粒子（3–5 天）** —— CPU 粒子 + 内置发射器 + 场景落盘；不追求 GPU 粒子。
7. **编辑器 Profiler 面板 + Preferences + 布局持久化（1 周）** —— 编辑器产品化第二波，
   三件都小，合起来能明显改善日常体验。
8. **多场景 + 构建设置（1 周）** —— 场景清单、新建空场景 / 多开、平台预设。
   项目一大，"一张大地图"会先撑不住。
9. **TAA（1 周）** —— 历史缓冲 + 运动向量 + 重投影；与 FXAA 二选一由用户配置。
   这是渲染侧最贵的一刀，放在玩法闭环之后。
10. **CSM（3–5 天）** —— 级联划分 + 每级拟合 + 级间过渡；与 TAA 独立，可并行。

P1 剩下的四项（morph / 脚本 API 补面 / 自动保存 / 手柄）穿插着做，不必占整刀。
再往后才是 **LOD / 遮挡剔除** 与 **ECS / 作业系统** —— 等实体数真的上万再动，
现在 rapier 才是瓶颈，换 ECS 不会让 1000 个互挤刚体变快。

**贯穿始终的两条**：每刀都配"先证红"的回归测试；每刀都把新增的"不能推翻的约束"
写进 [`决策记录.md`](决策记录.md)。

## 八、已经做对了的地方（别在重构里弄丢）

- **编辑器 Play 与独立游戏共用同一段 `World::update`** —— 多数自制引擎在这里分叉
  成两套运行时，最后行为不一致（项目设置同样是单入口）。
- **帧调度纪律**：`frame_policy` 停帧 + `AutoNoVsync` 上屏 + `frame_probe` 探针，
  输入→光子延迟压到 ~20 ms；空闲 CPU 0.00%。
- **稳态性能有量化**：2000 实体纯视觉 13 µs/帧、热路径零分配；渲染侧实例化
  2225 → 344 µs/帧、剔除 3295 → 1146 µs/帧，全部同机背靠背量过。
- **Prefab 带 Apply / Revert 与来源追踪** —— Unity 级特性，同类自制引擎很少做到。
- **交互细节扎实**：Undo 快照分步、Gizmo 参考线锚定防抽搐、层级拖拽防环、
  拾取用射线 × 世界 AABB（不是包围球）。
- **脚本系统有工程化**：编译缓存 + 热重载 + 指令预算沙箱，崩溃 / 死循环不拖垮引擎。
- **测试纪律**：458 条回归测试，每条先证明旧实现下会红。
- **数据即文本**：场景 / 预制体 / 清单 / 输入映射全 RON —— 版本控制友好，
  也是 Agent-Native 路线的地基。
- **无头三入口**：`--check`（引用完整性）/ `--headless`（固定 dt 逐位可复现）/
  `--screenshot`（同机逐字节一致）—— "改 → 查 → 验 → 看"闭环。

## 九、战略方向：Agent-Native

> **目标**：用户的 AI 智能体（Cursor / Claude / 任意支持 MCP 的客户端）能够**深度、
> 精确、可验证地**操作本引擎做游戏开发 —— 不是"截图点按钮"，而是像人类开发者一样
> 读写项目、运行检查、拿到可机读的结果。
>
> **架构判决式**：往后的架构决策都要过一问 —— **「智能体没有鼠标时，这条路走得通吗？」**

### 支柱与现状

| # | 支柱 | 状态 | 说明 |
|---|---|---|---|
| 1 | **数据即文本** | ✅ | 场景 / 预制体 / 清单 / 输入映射全 RON、稳定 ID、serde 向后兼容 —— 智能体可直接读写、diff、批量改 |
| 2 | **程序化验证** | ✅ | `xgame-editor --check <项目>`：退出码 0=干净 / 1=加载失败 / 2=悬空引用，秒级、可进 CI |

### 为什么这条路线对本引擎成立

1. **纯文本数据**是前提 —— Unity 的 YAML + GUID 混合体反而难智能体友好地整段改写；
   我们的 RON 场景人类可读、结构扁平。
2. **单一运行时**意味着智能体在无头环境验证的行为与玩家实际跑的完全一致 ——
   不存在"编辑器里对、打包后坏"。
3. **小而清晰的 crate 边界**让 MCP 工具直接调库，而不是模拟 UI 输入。
4. `--check` 已证明闭环模式：**改 → 一条命令 → 退出码**。后续每个能力都按同样模式
   给无头等价物。

### 近期计划（按序）

1. ✅ MCP server 最小工具集（7 工具）。
2. ✅ 无头运行 + 截图（`--headless` / `--screenshot` / `run_headless`）。
3. **场景 schema 导出**：`--export-schema`，字段、类型、默认值一次导出（支柱 8）。
4. **资产 GUID 落地后**给 MCP 补 `asset_list` / `asset_import` —— 智能体需要"看见"
   资产树，而不只是场景。
5. 每步配回归测试 + 文档，沿用"先证红"。
