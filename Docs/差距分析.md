Bloom + 天空 IBL + 实例化 + 剔除 + FXAA），**资产管线这个唯一的 P0 也已清空**
（GUID + `.meta` + 资产库诊断 + 资源浏览器，见 PLAN 三十二）。内容层四件套里
**角色控制器、游戏 UI、材质资产与导入参数接线、粒子系统已落地**，
**相机实体（PLAN 三十八）补上了"玩法闭环"的最后一块**：此前独立游戏的机位是写死的
(5,5,5)→原点，任何"第三人称 / 第一人称 / 切机位"的玩法都做不出来；
内容层观感与玩法这一层**已经齐平**；真正的差距集中在
**编辑器产品化**（Profiler 已落地，剩 Preferences / 布局持久化 / 多场景 / 自动保存）。

一句话排序：**内容层收口，转做编辑器产品化；渲染只差 TAA 与 CSM 两刀，
规模问题（LOD / ECS）等实体数真的上来再动。**
CI 是半小时的零风险收益，应该立刻做，不占优先级档位。

## 八、已经做对了的地方（别在重构里弄丢）

- **编辑器 Play 与独立游戏共用同一段 `World::update`** —— 多数自制引擎在这里分叉
  成两套运行时，最后行为不一致（项目设置同样是单入口）。
- **帧调度纪律**：`frame_policy` 停帧 + `AutoNoVsync` 上屏 + `frame_probe` 探针，
  输入→光子延迟压到 ~20 ms；空闲 CPU 0.00%。
- **稳态性能有量化**：2000 实体纯视觉 13 µs/帧、热路径零分配；渲染侧实例化
  2225 → 344 µs/帧、剔除 3295 → 1146 µs/帧，全部同机背靠背量过。
- **Prefab 带 Apply / Revert 与来源追踪** —— Unity 级特性，同类自制引擎很少做到。
- **交互细节扎实**：Undo 快照分步、Gizmo 参考线锚定防抽搐、层级拖拽防环、
  拾取用射线 × 世界 AABB（不是包围球）。
- **脚本系统有工程化**：编译缓存 + 热重载 + 指令预算沙箱，崩溃 / 死循环不拖垮引擎。
- **测试纪律**：664 条回归测试，每条先证明旧实现下会红。
- **数据即文本**：场景 / 预制体 / 清单 / 输入映射全 RON —— 版本控制友好，
  也是 Agent-Native 路线的地基。
- **无头三入口**：`--check`（引用完整性）/ `--headless`（固定 dt 逐位可复现）/
  `--screenshot`（同机逐字节一致）—— "改 → 查 → 验 → 看"闭环。

## 九、战略方向：Agent-Native

> **目标**：用户的 AI 智能体（Cursor / Claude / 任意支持 MCP 的客户端）能够**深度、
> 精确、可验证地**操作本引擎做游戏开发 —— 不是"截图点按钮"，而是像人类开发者一样
> 读写项目、运行检查、拿到可机读的结果。
>
> **架构判决式**：往后的架构决策都要过一问 —— **「智能体没有鼠标时，这条路走得通吗？」**

### 支柱与现状

### 为什么这条路线对本引擎成立

1. **纯文本数据**是前提 —— Unity 的 YAML + GUID 混合体反而难智能体友好地整段改写；
   我们的 RON 场景人类可读、结构扁平。
2. **单一运行时**意味着智能体在无头环境验证的行为与玩家实际跑的完全一致 ——
   不存在"编辑器里对、打包后坏"。
3. **小而清晰的 crate 边界**让 MCP 工具直接调库，而不是模拟 UI 输入。
4. `--check` 已证明闭环模式：**改 → 一条命令 → 退出码**。后续每个能力都按同样模式
   给无头等价物。

### 近期计划（按序）

1. ✅ MCP server 最小工具集（8 工具，含资产树 `asset_list`）。
2. ✅ 无头运行 + 截图（`--headless` / `--screenshot` / `run_headless`）。
3. **场景 schema 导出**：`--export-schema`，字段、类型、默认值一次导出（支柱 8）。
4. **资产 GUID 落地后**给 MCP 补 `asset_list` / `asset_import` —— 智能体需要"看见"
   资产树，而不只是场景。
5. 每步配回归测试 + 文档，沿用"先证红"。
