## 4. 数据模型

### 4.0 先回答：是 ECS 吗？

**是 ECS，但只是"ECS 为内核"，不是"ECS 即全部"。**

| 层 | 是不是 ECS | 说明 |
|---|---|---|
| 存储 | 是 | 实体 = ID + archetype/chunk；组件 = 列；查询按 archetype 匹配 |
| 执行 | 是 | 系统 + 阶段 + 访问声明；调度器按读写集并行 |
| 资源 | 不是 | 时间 / 输入 / 渲染设置 / 资产库是单例 `Resource`，不是实体 |
| 引擎服务 | 不是 | RenderGraph、AssetDatabase、PhysicsBackend、CommandJournal、AgentSession 是普通 Rust 服务 |
| 世界设施 | 不硬凑 | 层级、事件、命令、快照是 `World` 的一等公民，不用"空组件"模拟 |
| 编辑器 / 工具 | 不是 | 协议客户端，不塞进 ECS |

对使用者（人 / AI），心智模型仍是 **实体 + 组件 + 脚本**（Unity 式），不要求写
system；对引擎，system 是执行模型，query 是访问模型，registry 是描述模型。

**和 Bevy 的区别**：Bevy 把 ECS 当用户 API；我们把 ECS 当内核，用户主要面对
实体 / 组件 / 脚本与命令 / 查询协议。**和 Unity 的区别**：Unity 的
GameObject/Component 是作者模型，底层不保证 archetype；我们把作者模型与存储模型
分开，两者由注册表对齐。

**为什么选 ECS 作内核**：缓存局部性、查询可并行、迭代顺序可确定、注册表能同时
生成 schema / 命令 / 查询 / Inspector / Agent 工具。

**代价与边界**：结构变更要走命令缓冲与 archetype 迁移；archetype 可能碎片化；
不承诺"任意组件组合都零成本"。缓解：延迟命令、chunk 容量预留、标签组件、
稀有组件走稀疏集，以及一条设计规则——**不为一次性组合新建 archetype**。

一句话：**ECS-first，不是 ECS-only。**

### 4.1 身份：三种 ID，各管一件事

```rust
/// 持久身份：项目级单调分配，永不复用，跨文件 / 跨进程 / 存档都用它。
pub struct EntityId(u64);

/// 运行时句柄：O(1) 访问，generation 防悬垂。
pub struct EntityKey { index: u32, generation: u32 }

/// 资产身份：GUID v7，导入时生成，改名 / 移动不断链。
pub struct AssetId(Guid);
```

| ID | 作用域 | 谁引用 | 分配 | 生命周期 |
|---|---|---|---|---|
| `EntityId` | 整个项目（跨场景 / 预制体 / 存档） | 父引用、预制体来源、存档、Agent 协议、脚本 | 项目文件存 `next_entity_id` 水位；各场景 / 预制体记录本地最大值供独立校验，载入时 reserve | 永不复用；删除即作废 |
| `EntityKey` | 单次运行 | 引擎内部热路径 | 实体表槽位 | 随世界重建；generation 递增 |
| `AssetId` | 整个项目 | 场景 / 预制体 / 材质 / 脚本 / Agent | GUID v7，导入时生成 | 永不变；删除后进入 tombstone |

**名字与路径不是身份。** `EntityPath`（如 `/Level/Room/Door`）由层级派生，只用于
人和 AI 寻址；解析必须唯一，重名 / 歧义一律拒绝（继承当前 MCP 的纪律）。
改名、移动父节点不会让任何引用断链，因为引用只认 `EntityId` / `AssetId`。

**为什么实体 ID 是项目级而不是文件级：** 当前"每个文件内唯一"逼出了
`source_id`、身份侧车、预制体重复 ID 不许修等一整套复杂度。项目级 ID 让嵌套预制体、
跨文件引用、存档、多人协作都退化成同一个问题；代价是分配器要持久化（一个 u64 水位）。

### 4.2 组件：注册表驱动，列式存储

```rust
#[derive(Component, Clone, Debug)]
#[component(id = 0x0101, name = "core.transform")]
pub struct Transform {
    #[field(unit = "m", ui = "vec3")]
    pub position: Vec3,
    #[field(ui = "quat")]
    pub rotation: Quat,
    #[field(unit = "×", ui = "vec3", min = 0.0001)]
    pub scale: Vec3,
}
```

**注册表（`xgc-reflect`）是唯一真相源。** 每个组件的描述符包含：

- 稳定 `ComponentId`（u32，按注册顺序编号，落盘 / 协议都用它）；
- 字段名、类型、默认值、范围、单位、可变性、UI 提示、文档、示例；
- 存储布局（列式字段偏移）、clone / drop / 序列化 / 校验函数指针；
- 版本与迁移函数（只在格式破坏时使用一次）。

**存储**：archetype + chunk。

```text
Archetype { component_ids: [ComponentId; N] }   // 按 ID 排序，匹配即 memcmp
  └─ Chunk（16 KiB）
       ├─ EntityId[] / EntityKey[]
       ├─ Transform 列（每条 40 B）
       ├─ Velocity 列
       └─ changed_tick 位图（每个组件一条）
```

- **组件级列式**：同一组件的值在 chunk 内连续；查询按 chunk 批处理，缓存命中率高。
- **热组件拆分**：`Transform` / `GlobalTransform` / `Velocity` 这类每帧必读的字段
  单独成列；冷字段（名字、脚本参数）放侧表，不污染热 chunk。
- **标签组件**零大小，只参与 archetype 匹配（`Player`、`Static`、`Disabled`）。
- **不做每实体 `HashMap<TypeId, Box<dyn Any>>`**：当前 `ComponentMap` 只被两个运行时
  状态使用，却让"组件"这个词有两套语义；新框架里运行时状态也是组件。
- **容量预留**：archetype 按预期实体数预留 chunk；结构变更只 memcpy 迁移，不逐条分配。

**变更检测**：世界每进入一个阶段 `tick += 1`；写组件时把该 chunk 的对应位图置位。
`Changed<T>` / `Added<T>` 查询按位图过滤；渲染提取、物理同步、UI 重建都靠它做增量，
而不是"每帧全量比较"。

### 4.3 查询

Rust 侧（静态、零成本）：

```rust
fn move_players(
    time: Res<Time>,
    mut q: Query<(&PlayerInput, &mut Velocity, &Transform), Without<Frozen>>,
) {
    for (input, mut vel, tf) in q.iter() {
        vel.0 = input.dir * 5.0;
    }
}
```

Agent 侧（动态、可序列化）：

```json
{
  "from": "scene",
  "select": ["entity.id", "entity.name", "core.transform.position", "game.health.hp"],
  "filter": {"and": [
    {"has": "game.health"},
    {"eq": ["core.layer", 3]},
    {"aabb": [[-10, 0, -10], [10, 4, 10]]}
  ]},
  "order": ["entity.id"],
  "limit": 200,
  "include_defaults": false
}
```

两条路径共享同一个**查询计划编译器**：字段路径 → 组件列 + 偏移；过滤 → 位图 / 索引；
排序 → 稳定键。动态查询的编译结果按 `(schema_version, query_hash)` 缓存，重复调用
只付执行成本。

**索引策略**：

| 索引 | 维护时机 | 用途 |
|---|---|---|
| `EntityIndex`（ID → key） | 实体创建 / 销毁 | O(1) 查找；消灭 67 处线性 `find_entity` |
| `NameIndex` | 改名命令 | 人 / AI 按名字寻址；重名返回歧义诊断 |
| `SpatialIndex`（物理 BVH） | 物理步进 | AABB / 球 / 射线查询 |
| `RefIndex`（AssetId → 实体集合） | 资产引用变更 | "谁用了这张贴图"、删除前影响分析 |
| `TagIndex`（bitset） | 标签增删 | 稀有标签的快速过滤 |

**顺序确定性**：archetype 按创建顺序、chunk 按分配顺序、行按插入顺序；需要"按 ID
排序"的查询显式排序。任何依赖 `HashMap` 迭代顺序的仿真逻辑都视为 bug（§5.2）。

### 4.4 命令：唯一的结构性写路径

```rust
pub enum Command {
    Spawn { id: EntityId, parent: Option<EntityId>, name: String, components: Vec<ComponentInit> },
    Despawn { entity: EntityId },
    AddComponent { entity: EntityId, component: ComponentId, value: Value },
    RemoveComponent { entity: EntityId, component: ComponentId },
    SetField { entity: EntityId, component: ComponentId, path: FieldPath, value: Value },
    Reparent { entity: EntityId, parent: Option<EntityId>, keep_world: bool },
    InstantiatePrefab { prefab: AssetId, parent: Option<EntityId>, transform: Transform },
    ApplyPrefab { instance_root: EntityId },
    RevertPrefab { instance_root: EntityId },
    SetProjectConfig { path: FieldPath, value: Value },
    ImportAsset { path: String, settings: ImportSettings },
    MoveAsset { from: String, to: String },
    // …按需增加；每个命令都必须能生成逆命令
}
```

**事务模型**：

```text
plan(ops, base_revision)
  → 校验（类型 / 范围 / 引用 / 层级环 / ID 唯一 / 路径）
  → 诊断（error 即拒绝；warning 随计划返回）
  → 预测 diff（受影响实体 / 文件 / 字节数）
  → plan_id
apply(plan_id, base_revision, idempotency_key)
  → 二次校验 revision（乐观并发）
  → 生成逆命令 + before-image
  → 多文件原子提交（journal + staging + rename + 恢复标记）
  → 新 revision + 实际 diff + tx_id
revert(tx_id)
  → 应用逆命令（新 revision，不是时间旅行）
```

**为什么"计划"和"应用"分开**：AI 需要先看"我准备改什么、会坏什么、影响哪些文件"，
人需要审批；编辑器需要把一次拖拽合并成一个事务；CI 需要 dry-run。当前 MCP 只能
"直接写，写坏了再读回来"，没有预览，也没有回滚。

**成本模型**：计划 / 校验是 `O(ops + 触碰的实体/字段)`，不是 `O(world)`；引用检查
走反向索引，层级环检测只沿被改动的父链走。大事务（10k 条）也要能在毫秒级给出
diff，否则"先计划"会被绕过。

**何时结算**：

| 场景 | 结算点 | 语义 |
|---|---|---|
| 系统内 `Commands` | 当前阶段屏障 | `spawn` 立刻分配 `EntityId`，但实体在屏障后才可查询 |
| 脚本结构性修改 | 当前阶段屏障 | `spawn` 返回 ID；同帧后续命令可引用；查询看不到 |
| 外部编辑（编辑器 / MCP / AI） | 帧边界 | 一次事务一个 revision；应用后下一帧可见 |
| 热重载 | 帧边界 | 与外部编辑同队列，顺序确定 |

统一成"屏障结算"是为了消灭当前引擎"场景立即生效、物理下一帧才建"的隐式时序：
**ID 立即可用，状态在屏障后一致**。这条规则写进协议文档，AI 不需要逐帧猜。

### 4.5 层级与变换

- 存储：`Parent(EntityId)` + `Children(Vec<EntityId>)` 两列；子列表由命令维护，
  读路径不再"每次现算"。
- 传播：按深度分层；同一层内每个实体只有一个父，写 `GlobalTransform` 无竞争，
  可并行；合并按 `EntityKey` 顺序，结果确定。
- 脏标记：局部变换变了才把子树标脏；未变的子树整段跳过（当前 `world_matrices()`
  每次全量重建并分配）。
- 世界矩阵只算一次，渲染 / 物理 / 音频 / UI 都读同一份 `GlobalTransform`；
  当前"每个消费者各解一遍"的现象消失。
- 重挂父节点走 `Reparent { keep_world }` 命令，保留世界变换；成环在计划阶段拒绝。

### 4.6 快照、回放与状态哈希

```rust
pub struct Snapshot {
    pub revision: WorldRevision,
    pub next_entity_id: u64,
    pub entities: Vec<EntityRecord>,     // 按 EntityId 排序
    pub components: ComponentColumns,    // 按 ComponentId 排序的列
    pub resources: ResourceBlob,         // Time / RNG / 全局变量
    pub physics: PhysicsSnapshot,        // 刚体位姿 / 速度 / 睡眠状态
}
```

- **快照是二进制的**（registry 驱动的 writer / reader），不经过文本；10k 实体目标
  ≤ 20 ms、≤ 20 MB（未压缩）。
- **状态哈希**：每个 chunk 维护脏哈希，世界哈希 = Merkle 组合；每帧只重算脏 chunk。
  `sim.hash()` 返回 `u64`，用于"两次运行是否逐位相同"和"从哪一帧开始分叉"。
- **回放 = 初始快照 + 输入帧序列 + 固定 dt + 命令日志**；`sim.replay` 逐帧比对
  state hash，返回首个分歧帧与该帧的差异摘要。
- **脚本状态**：脚本的每实体状态存为 `ScriptState` 组件（按脚本 GUID + 实体），
  进快照；Lua VM 本身不进快照。这是"脚本必须把状态放进世界"的硬约束，也是
  可回放的前提。当前引擎的"驻留 id 永不清"解决的是另一件事（热重载身份），
  新框架用 GUID 做键，天然稳定。
- **物理状态**：快照存刚体位姿 / 速度；恢复时直接写回物理后端，不重放历史。

### 4.7 序列化与 schema

**两种形态，一个模型**：

| 形态 | 用途 | 特点 |
|---|---|---|
| 文本 RON | 人 / AI / git / diff | 稳定字段序、显式 ID、默认值省略、`save→load→save` 第二轮不动点 |
| 二进制 cooked | 运行时加载 | 头部 magic + 格式版本 + schema 哈希；mmap；不解剖文本 |

**schema 由注册表生成**，不再手写 3503 行目录：

```json
{
  "format_version": 1,
  "types": [{
    "id": "core.transform",
    "kind": "struct",
    "summary": "局部变换（相对父节点）",
    "fields": [
      {"name": "position", "ty": "vec3", "unit": "m", "default": [0,0,0],
       "ui": "vec3", "doc": "相对父节点的平移"},
      {"name": "rotation", "ty": "quat", "default": [0,0,0,1], "ui": "quat"},
      {"name": "scale", "ty": "vec3", "default": [1,1,1], "min": 0.0001}
    ]
  }]
}
```

- 确定性：类型按 `ComponentId`、字段按声明顺序；无时间戳 / 随机 ID；两次导出逐字节相同。
- 防漂移：不再靠"穷举解构"手写测试，而是 `xtask` 生成注册表 + CI 比对生成物；
  手写注册表与源码不一致时编译失败（生成文件带哈希）。
- 迁移：`format_version` + 一次性 `xgc migrate`；运行时遇到未知版本直接拒绝，
  不做双读 / 自动迁移。

### 4.8 扩展成本：现在 vs 目标

| 任务 | 现在的成本 | 目标的成本 |
|---|---|---|
| 加一个内建组件 | ≈20 处 match / 数组 / 目录 + 2 处测试 | 1 个组件文件 + 1 行注册（`xtask` 生成注册表） |
| 给组件加一个字段 | 组件 + 磁盘投影 + schema + 测试 | 1 处字段声明（derive 生成其余） |
| 加一个脚本 API | `ctx.rs` + `lua_api.rs` + 清单 + 文档 + 计数断言 | 1 个命令 / 查询声明（生成绑定、清单、文档） |
| 加一个渲染 pass | `render()` + 3 个宿主 + bind group + 测试 | 1 个 graph node + 资源声明 |
| 加一个 MCP 工具 | `tools.rs` 手写 JSON Schema + 测试 | 1 个协议方法（生成 schema 与适配） |

这张表是"AI 可维护"的核心：**AI 改引擎的边际成本，取决于新增一个概念要碰几处。**

## 5. 调度、并行与时间

### 5.1 阶段与系统

```text
Stage::PreSim     输入快照 / 命令结算 / 流式完成
Stage::FixedSim   固定步系统（玩法 / 角色 / 物理前置）
Stage::FixedPost  物理回写 / 碰撞事件 / 触发器 / 动画事件
Stage::Sim        update 系统（脚本 / 动画 / UI / 音频 / 粒子）
Stage::PostSim    命令结算 / 层级传播 / 可见性 / 提取
Stage::Render     渲染线程消费 FrameSnapshot
```

系统声明访问集，调度器构建冲突图：

```rust
schedule.add(Stage::FixedSim, move_players)
    .after(input_snapshot)
    .before(physics_step)
    .reads::<PlayerInput>()
    .writes::<Velocity>();
```

- **冲突判定**：读写同一组件列 / 同一资源即冲突；冲突系统按注册顺序串行，
  无冲突系统并行。
- **合并顺序固定**：并行系统的副作用（命令、事件、统计）在阶段屏障按注册顺序提交；
  浮点结果不依赖线程完成顺序。
- **命令屏障**：每个阶段结束统一结算；系统内看不到本阶段其它系统的结构改动，
  避免"跑一半世界变了"。
- **阶段不是越多越好**：默认六个阶段；新增阶段必须说明"为什么现有屏障不够"。

### 5.2 确定性并行的十条规则

| # | 规则 | 违反的典型写法 | 门禁 |
|---|---|---|---|
| 1 | 仿真不读墙钟 | `Instant::now()` / `SystemTime` | `xtask lint-det` 扫描 |
| 2 | 仿真不用全局随机 | `rand::thread_rng()` | 只允许 `World::rng(stream)` |
| 3 | 迭代顺序稳定 | `HashMap` 迭代、`HashSet` 去重后直接消费 | 仿真 crate 禁 `HashMap` 迭代（clippy / 审查） |
| 4 | 浮点归约顺序固定 | `par_iter().sum()` | 并行归约必须按分片顺序合并 |
| 5 | 实体 ID 不按地址 / 指针 | `as *const` 做键 | 只允许 `EntityId` / `ComponentId` |
| 6 | 物理岛按最小实体 ID 排序 | 按线程完成顺序 | 物理后端契约 |
| 7 | 脚本按实体 ID 排序执行 | 按 HashMap 顺序 | 脚本调度器 |
| 8 | 事件按发射顺序消费 | 多线程并发 push 后排序 | 事件队列按系统注册顺序合并 |
| 9 | 并行度不改变结果 | 分片数影响数学 | 测试用 1 / 2 / 8 线程各跑一遍比对哈希 |
| 10 | 时间只来自固定步 | 渲染 dt 直接进玩法 | 玩法系统只读 `FixedTime` |

**跨平台确定性**的边界：同二进制 + 同平台逐位一致；跨平台用**快照**而不是输入重放
来迁移状态。需要跨平台逐位的项目可以开 `det-math`（软件 `sin/cos/sqrt` + 定点物理），
代价是性能；默认不开。这个取舍要写进项目配置，而不是藏在代码里。

### 5.3 固定步与插值

- 固定步默认 1/60 s，可配置（30 / 60 / 120）；累加器 + 最多 5 步，防死亡螺旋。
- **玩法 / 物理 / 动画（含事件）用固定步**；UI / 音频 / 粒子用渲染帧 dt（与当前引擎
  同一取舍），但**不反向影响玩法状态**。动画在渲染帧只做姿态插值，不推进时钟。
- 渲染用 `alpha = accumulator / fixed_dt` 在上一帧与当前帧变换间插值；物理体不插值
  （直接读最近固定步），需要平滑的视觉体加 `Interpolated` 标记。
- `time_scale` 只缩放固定步推进；暂停 = 不消费累加器；单步 = 手动推一个固定步。
- 仿真时间 = `tick × fixed_dt`，不是墙钟累计；回放 / 无头 / 截图都用同一时钟。

### 5.4 作业系统

- 工作窃取双端队列；任务粒度 = chunk（不是实体），避免每实体一个任务的开销。
- 并行原语只有三种：`par_for_chunks`、`par_for_entities`（稳定分区）、
  `par_systems`（调度器内部）；禁止嵌套并行，防止线程饥饿。
- 主线程在等待 GPU / IO 时参与工作窃取；仿真协调线程不参与重活，保证屏障及时。
- 每个任务带 `budget`（最大实体数 / 最大微秒），超预算拆任务，不无限递归。
- 线程数可配；CI 用 1 / 2 / 8 三档跑确定性测试。

### 5.5 遥测与预算

每个系统每帧产出一条 `SystemStats`：

```rust
pub struct SystemStats {
    pub system: SystemId,
    pub cpu_ns: u64,
    pub alloc_count: u32,
    pub alloc_bytes: u64,
    pub entities_visited: u32,
    pub chunks_visited: u32,
}
```

- `FrameTrace` 环形缓冲保留最近 N 帧；`sim.profile` / 编辑器 Profiler / 基准共用。
- 预算写在注册表里（每系统 / 每阶段 / 每帧），超预算在 CI 红，不在运行时静默降级。
- 基准必须断言"真的跑了"（继承当前纪律）：实体数 / 访问计数 / 哈希变化，三者至少
  一项非零，否则判基准无效。

### 5.6 反模式清单

| 反模式 | 后果 | 替代 |
|---|---|---|
| 每帧全表扫描找"谁有 X" | O(n) × 系统数 | 组件列 / 标签位图 / 索引 |
| `HashMap<EntityId, T>` 进热路径 | 哈希 + 指针追逐 | 组件列 + `EntityIndex` |
| 每帧 `collect()` / `format!` | 分配抖动 | 复用 `Vec` / `SmallVec` / 写入预分配缓冲 |
| 系统内加锁 | 阻塞 worker | 访问集声明，调度器保证不冲突 |
| 阻塞 IO 进仿真 | 帧时间尖刺 | 异步 IO + 下一帧完成事件 |
| "先跑一遍再修正" | 双倍工作 | 计划阶段校验 |
| 静默截断 / 钳制 | AI 以为生效 | 拒绝 + 诊断码 + 可接受范围 |

## 6. 渲染

### 6.1 目标与能力分层

渲染的目标不是"功能最多"，而是**在 1080p / 中端 GPU 上，把 10 万实例的 CPU 提交
压到 1.5 ms 以内，并让每条优化都能被像素测试判对错**。

能力分三层，按设备能力自动选择，低层永远是正确性兜底：

| 层 | 内容 | 依赖 | 何时启用 |
|---|---|---|---|
| Tier 0 | 经典实例化 + CPU 剔除 + 前向 PBR + CSM | 任何 wgpu 设备 | 默认兜底 |
| Tier 1 | GPU 剔除 + indirect + bindless 材质 + 聚簇光照 | `INDIRECT_FIRST_INSTANCE` 不需要；`MULTI_DRAW_INDIRECT` / binding array 可选 | 设备支持且场景规模值得 |
| Tier 2 | 簇（meshlet）剔除 + 虚拟几何 + 软件光栅兜底 | compute + storage + indirect | 大世界 / 高面数项目，默认关 |

**不承诺"所有设备都走 Tier 2"**。每层都要有独立的像素测试与性能基准；降层必须
画面等价（允许性能差异，不允许内容缺失）。

### 6.2 RenderGraph

当前引擎的 pass 顺序硬编码在 1233 行的 `render()` 里，帧图还在编辑器 / 游戏 / 截图
三个宿主各抄一遍。新框架用声明式帧图：

```rust
let mut graph = RenderGraph::new();
let depth = graph.create_texture("depth", Depth32Float, size);
let hdr   = graph.create_texture("hdr", Rgba16Float, size);

graph.add_pass("shadow", |p| {
    p.writes(depth);
    p.draw_shadow_casters(&shadow_plan);
});
graph.add_pass("cluster", |p| {
    p.reads(depth);
    p.writes(light_grid);
    p.compute(cluster_build);
});
graph.add_pass("opaque", |p| {
    p.reads(depth);
    p.writes(hdr);
    p.draw_indirect(&opaque_batches);
});
graph.add_pass("post", |p| {
    p.reads(hdr);
    p.writes(swapchain);
    p.post_chain(&post_settings);
});
```

帧图负责：

- **资源生命周期**：transient 纹理 / 缓冲从堆里借，按 lifetime 复用（别名）；
- **屏障**：根据读写声明自动插入，不手写 `TextureBarrier`；
- **队列**：图形 / 计算 / 拷贝三条队列的依赖与信号量；
- **降级**：某 pass 不支持时整段跳过（而不是跑一遍乘 0），与当前"默认关 = 整段跳过"
  的纪律一致；
- **可视化**：帧图可导出 DOT / JSON，编辑器能看每个 pass 的输入输出与耗时。

**为什么值得重写**：加一个 pass 从"改 3 个宿主 + 手写 barrier + 猜顺序"变成
"加一个节点 + 声明资源"；这也是 AI 能安全改渲染的前提。

### 6.3 提取（extraction）

`sim` 在 `PostSim` 产出不可变 `RenderFrame`：

```rust
pub struct RenderFrame {
    pub revision: WorldRevision,
    pub camera: CameraData,
    pub instances: InstanceBuffer,      // SoA：transform / bounds / mesh / material / flags
    pub skinned: SkinnedBuffer,         // 骨骼调色板 / 蒙皮矩阵
    pub lights: LightBuffer,
    pub ui: UiDrawList,
    pub changed: DirtyRanges,           // 只上传变化的区间
    pub stats: RenderStatsSeed,
}
```

- 提取按 chunk 并行；`Changed<T>` 决定脏区间，GPU 缓冲只写脏段（当前每帧整段重写
  `draw_buffer`，896 KiB/帧）。
- 可见性预筛在提取阶段做**保守**粗筛（超大 AABB 直接保留），精确剔除交给 GPU；
  不在 CPU 逐实体做最终判定（当前 CPU 提交 3.3 ms 的主因）。
- `RenderFrame` 不可变，渲染线程 / 主线程只读；编辑器面板读同一份快照。
- 提取 DTO 是渲染与世界的唯一契约，渲染 crate 不出现 `World` / `Entity` 类型。

### 6.4 GPU 驱动剔除与批次

```text
实例缓冲（storage）
   │
   ├─ compute: 视锥剔除 + HZB / 深度金字塔遮挡 + LOD 选择 + 簇剔除
   │      → visible_indices（压缩后的实例索引）
   │      → indirect args（每批 / 每簇）
   │
   └─ 图形: draw_indexed_indirect（每批一次；支持 multi-draw 时合并）
```

- **HZB 的来源**：优先用主通道深度（前向 + 深度预通道合并，深度测试 `Equal`），
  其次用上一帧深度做保守剔除；不用"同帧全几何预通道只为遮挡"——当前实测
  +44% GPU，是结构性重复（决策记录 §八十七）。
- **批次键**：`(mesh, material, pipeline, lod)`；同键实例连续存放；半透明单独排序。
- **Tier 2 簇**：离线构建 meshlet（每簇 ≤ 128 三角形 / 64 顶点），簇级包围盒 +
  法线锥；GPU 逐簇剔除 + LOD；光栅化仍走普通 index buffer（不依赖 mesh shader）。
- **CPU 只做三件事**：提交帧图、绑定少量全局资源、处理"设备不支持"的降级。
  目标是 draw calls ≤ 500、CPU 提交 ≤ 1.5 ms（100k 实例）。
- **可见性解释**：每个实例记录被哪一级剔除（frustum / hzb / lod / distance /
  layer），`render.explain(entity)` 可查；AI 排"为什么没画"不用猜。

### 6.5 材质与着色器

**材质 = 着色器 + 参数块 + 贴图槽**，不是"一堆 uniform 分支"。

```rust
pub struct MaterialType {
    pub shader: AssetId,                 // .wgsl 资产
    pub params: SchemaId,                // 由 naga 反射生成
    pub textures: Vec<TextureSlot>,      // 槽名 / 维度 / 采样器
    pub variants: VariantKey,            // 关键字组合
}
```

- **反射生成 schema**：用 `naga` 解析 WGSL 的 bind group / uniform / storage 布局，
  生成字段表（名字、类型、偏移、默认值、范围），直接进注册表 → Inspector / AI /
  校验 / 序列化全部免费。当前引擎材质只有 2 个槽、参数逐 draw 手写 uniform，
  加一个材质参数要改 Rust + WGSL + Inspector 三处。
- **变体系统**：`#ifdef` 关键字（阴影 / 蒙皮 / 雾 / 调试视图）；离线编译成 pipeline
  cache，运行时只查表；变体爆炸用"基础管线 + 动态分支"控制。
- **bindless**：材质参数进 storage buffer，贴图进 binding array；每实例一个
  `material_index`，不再每批 `set_bind_group`。设备不支持时退回"每材质一个 bind group"
  的 Tier 0 路径，接口不变。
- **着色器工具链**：`.wgsl` 文件 + 模块组合（`naga_oil` 风格的 import），支持
  热重载、错误定位到 `file:line:col`、离线校验；不再用 `format!` 拼内联字符串。
- **管线缓存**：磁盘缓存 key = 着色器哈希 + 布局 + 设备特性 + 变体；冷启动
  编译 ≤ 2 s，热启动 ≤ 200 ms；缓存损坏自动重建。

### 6.6 光照与阴影

| 能力 | 方案 | 默认 |
|---|---|---|
| 直接光 | 聚簇前向+（clustered forward+），最多 1024 盏灯 | 开 |
| 方向光阴影 | 4 级 CSM，纹素吸附，级间混合 | 开（有方向光时） |
| 点 / 聚光阴影 | 2D 深度图集（atlas），逐面 / 逐盏剔除 | 关（按灯开启） |
| 软阴影 | PCSS 可选，固定泊松盘（无随机） | 关 |
| 静态阴影缓存 | 静态几何阴影只渲染一次，动态物体叠加 | 开（可选） |
| 环境光 | 程序化天空 + IBL（预过滤 cubemap + BRDF LUT） | 开 |
| 反射探针 | 局部 cubemap 探针 | v2 再做 |

**继承当前引擎的亮度基线**（`intensity × π`、Bloom 阈值在曝光后、光晕在曲线前），
避免"新引擎画面整体暗 3.14 倍"这类翻案。阴影采样用固定盘 / 固定抖动序列，
保证截图逐字节可复现。

### 6.7 后处理与确定性

固定的后处理链（顺序不许随意插）：

```text
HDR(RGBA16F) → SSAO(可选) → TAA(可选) → Bloom(可选) → 曝光 → ACES → FXAA/FSR(可选) → UI
```

- **TAA 需要逐物体运动向量**（当前只有相机重投影，快速横移有拖影）；运动向量由
  `GlobalTransform` 上一帧 / 当前帧 + 蒙皮矩阵生成，进 `RenderFrame`。
- **抖动是帧号的纯函数**（Halton 序列），不用随机数；首帧 / 越界直通；历史缓冲
  做邻域钳制。
- **每个效果默认关，关着整段跳过**（不建纹理、不记 pass），且与开着时的基线逐位
  一致——这是当前引擎验证过的纪律，继续沿用。
- **截图确定性**：固定相机、固定帧号、固定采样序列、无墙钟；`render.capture`
  返回 PNG + hash + 机位 + 统计；CI 用 golden 图逐像素比对（容差按通道配置）。
- **调试视图**：wireframe / overdraw / normals / cluster / shadow cascade / LOD
  着色，全部走帧图节点，不影响生产路径。

### 6.8 性能预算与验证

| 指标 | 预算（1080p，中端独显） | 验证 |
|---|---|---|
| CPU 提交（100k 实例） | ≤ 1.5 ms | `bench_render_submit` |
| GPU 帧（不透明 + 阴影 + 后处理） | ≤ 8 ms | GPU timestamp |
| draw calls | ≤ 500 | `RenderStats` |
| 显存（100k 实例 + 2k 材质） | ≤ 3 GB | 分配器统计 |
| 管线冷启动 | ≤ 2 s | `bench_pipeline_cache` |
| 截图确定性 | 两次逐字节相同 | golden test |

**每条优化都要有 A/B 像素等价测试**（开 / 关渲染同一帧，逐像素比较），这是当前
引擎最有价值的渲染纪律之一；新框架把它做成测试宏，默认生成。

### 6.9 分阶段落地

1. **M2**：Tier 0 + RenderGraph + CSM + PBR + 后处理 + 截图（先追上当前画面）。
2. **M5a**：Tier 1 GPU 剔除 + bindless + 聚簇光照（性能主战场）。
3. **M5b**：Tier 2 簇 / 虚拟几何（可选，按项目规模决定）。
4. **M6**：GPU 粒子、体积雾、局部反射（v2 范围）。

## 7. 物理、动画、音频、UI、粒子

### 7.1 物理

**后端抽象**：`xgc-physics` 只暴露窄接口，rapier 是首个后端，不把 rapier 类型
漏进世界。

```rust
pub trait PhysicsBackend: Send {
    fn create_body(&mut self, desc: BodyDesc) -> BodyHandle;
    fn destroy_body(&mut self, body: BodyHandle);
    fn step(&mut self, dt: f32);
    fn write_back(&mut self, out: &mut PhysicsOutput);
    fn raycast(&self, ray: Ray, filter: QueryFilter) -> Option<Hit>;
    fn snapshot(&self) -> PhysicsSnapshot;
    fn restore(&mut self, snapshot: &PhysicsSnapshot);
}
```

- **确定性优先**：首个后端单线程 + `simd-stable`；物理岛按最小 `EntityId` 排序；
  约束顺序固定；删除体按 ID 排序；碰撞对规范化。这些是当前引擎已经验证过的
  逐位确定性前提（决策记录 §六十七），继续沿用。
- **岛级并行是 R&D，不是承诺**：M1 做 spike，判据是"1 / 2 / 8 线程结果哈希一致
  且 5k 动态体 ≤ 4 ms"；做不到就保持单线程 + SIMD，或评估 Jolt 后端。**不为了让
  基准好看而放弃逐位确定性**。
- **性能目标**：5k 动态盒 60 Hz ≤ 4 ms；20k 静态 + 1k 动态 ≤ 2 ms；睡眠体不参与
  求解；CCD 只对快速体开启；宽相增量更新。
- **查询**：raycast / shapecast / overlap，结果按 `(distance, EntityId)` 排序；
  层掩码语义与当前 `Layers` 一致（成员位 + 双侧相与）。
- **角色控制器**：运动学胶囊 + sweep + 台阶 / 坡度 / 贴地；碰撞事件在固定步后
  统一派发。
- **快照**：刚体位姿 / 速度 / 睡眠状态进 `PhysicsSnapshot`；恢复直接写回，不重放。
- **物理线程**：首版在仿真线程内；若后端可分离，M5 再评估独立物理线程（固定步
  同步点交换快照，语义不变）。

### 7.2 动画

- **数据**：glTF 导入为 `Clip { times, values, tangents, interpolation }`；逐通道
  轨道布局固定，CUBICSPLINE 原样保留（Hermite 采样，旋转归一化）。
- **状态机**：每层一台（base / upper / additive），参数表、状态、转移、逐条淡入
  时长；状态机是数据资产，AI 可读写。
- **混合**：基础层 + 多层 Override / Additive + 遮罩；根运动按轴消费，位移落到
  角色控制器或运动学体。
- **事件**：`AnimEvent { time, name }` 在固定步派发，循环跨界 / 一帧多圈都要正确。
- **蒙皮**：GPU 调色板（storage buffer 或 bone texture），每实例骨骼数上限由注册表
  声明；蒙皮在当前姿态算 bounds，供剔除使用（继承[决策记录](决策记录.md) §八十八的教训）。
- **运动向量**：上一帧 / 当前帧骨骼矩阵 + 物体矩阵，供 TAA。
- **IK / 重定向 / 根旋转**：v2，不阻塞首版；数据模型预留 `IkChain` 组件位。

### 7.3 音频

- kira 后端；固定三组总线（Sfx / Bgm / Voice），有效音量 = 声源 × 总线，主音量在
  主轨；默认全 1.0（当前踩过"默认 0 = 全局静音"的坑）。
- 空间化：监听者取主相机；`follow` 绑定实体；每渲染帧同步一次位置。
- 流式：长音频流式解码；短音效预解码；内存预算按类别。
- 遮挡 / 低通 / 混响：v2；接口预留 `AudioOcclusion`。
- 命令：播放 / 停止 / 调音量在帧末统一结算（与当前一致），不阻塞仿真。
- 确定性：音频不参与 state hash；但**触发事件**由仿真决定，回放时事件序列一致。

### 7.4 UI

- **数据驱动**：UI 是组件树（`UiNode` + `UiStyle` + `UiLayout`），不是代码；AI 可
  直接读写，Inspector 可生成。
- **布局**：flex / grid（`taffy` 或等价实现），确定性求解；文本用 `cosmic-text`
  排版 + 图集缓存，键 = 内容 + 字体 + 字号 + 宽度（对齐不进键）。
- **输入**：指针 / 键盘 / 手柄 / 触摸统一成 `UiEvent`；焦点导航（方向键、一格一帧、
  不回绕、同行优先）；指针捕获与失焦取消分开。
- **绘制**：产出 `UiDrawList`（quad / text / nine-slice / clip），渲染层合批；
  九宫格边距按图片像素换算。
- **时序**：UI 布局在 `Sim` 阶段最前，脚本本帧读到的点击状态是本帧的；脚本改的
  矩形下一帧参与命中（继承当前取舍，写进测试）。
- **缩放**：DPI / 安全区 / 多分辨率锚点；截图固定 DPI。

### 7.5 粒子

- **GPU 模拟**（compute）：发射器参数在组件里，粒子状态在 GPU 缓冲；CPU 只更新
  发射器与排序键。
- **确定性**：如果粒子参与玩法（伤害 / 碰撞），用固定种子 + 固定步，CPU 模拟；
  纯视觉粒子可用渲染帧 dt，不参与 state hash。
- **排序**：半透明粒子按深度排序；GPU 排序用 bitonic / radix（固定网络，确定）。
- **事件**：碰撞 / 死亡事件回读（有界、异步），供玩法消费；不回读则不产生同步点。
- **降级**：设备不支持 compute 时 CPU 模拟（数量上限降低），接口不变。

### 7.6 输入

- **设备层 → 语义层**：键盘 / 鼠标 / 手柄 / 触摸统一成 `Action`（按钮）与 `Axis`
  （轴）；`InputMap` 是数据资产，支持多绑定 / 修饰键 / 死区 / 重绑定。
- **状态**：电平 + 边沿（pressed / released）；每帧末清边沿；失焦取消 pressed /
  released，但保留设备物理事实（继承决策记录 §九十一的纪律）。
- **回放**：输入记录为 `(frame, action, value)`，不含墙钟；headless / 回放 / 测试
  都注入同一个 `InputState`，不另造模拟器。
- **UI 捕获**：指针在 UI 上时游戏输入按规则让位；焦点与捕获分开，视口外松手也要
  收到 released 边沿。
- **时序**：输入在帧首采样，仿真同帧消费；不引入"按键延迟一帧"。

## 8. 脚本与行为

### 8.1 语言选择

| 语言 | 定位 | 性能 | 安全 | 决策 |
|---|---|---|---|---|
| **Lua 5.4** | 玩法主语言 | 中（批处理后够用） | 沙箱成熟 | **v1 唯一必选** |
| Rust（cdylib） | 引擎扩展 / 高性能系统 | 高 | 受信任 | v1 支持，版本化 ABI |
| WASM | 可选的高性能用户逻辑 | 高 | 强沙箱 | v2 评估，接口预留 |
| C# / 多语言中立层 | — | — | — | **不做**（决策记录 D1 已否决） |

Lua 的选择理由不是性能，而是**AI 与人的可读性、热重载、沙箱、零编译**。性能问题
用"批处理 + 数据导向 API"解决，不换语言。

### 8.2 批处理行为模型

当前模型是"每实体每钩子一次 VM 调用"，1000 个 no-op 实体 562 µs/帧。新模型把
**模块**作为调度单位：

```lua
-- scripts/health.lua
local M = {}

function M.update(batch)
    for i = 1, batch:len() do
        local e = batch:entity(i)
        local hp = e:get("game.health.hp")
        if hp <= 0 then
            e:set("game.health.dead", true)
            e:emit("died")
        end
    end
end

return M
```

- 引擎每帧对每个**模块**调用一次 `update(batch)`；`batch` 是查询结果的只读视图 +
  写句柄，`batch:entity(i)` 返回轻量视图（不分配、不跨迭代持有），回调内不跨实体
  持有引用。
- **兼容写法**：如果脚本只定义了 `function update(entity)`，引擎在加载时把它包成
  "对每个实体调用"的循环。它仍然每实体一次 Lua 调用，但省掉宿主构造、预算重置与
  状态表查找，成本会明显下降；**要拿到数量级提升，必须用 batch 写法**。作者写法
  不变，性能按写法分档。
- `start` / `on_event` 仍可按实体派发（次数少）；结构性修改走命令队列。
- 目标：10k 个用 batch 写法的实体 ≤ 500 µs/帧（现状 5.6 ms，逐实体写法）。

### 8.3 沙箱与能力

| 机制 | 规则 |
|---|---|
| 指令预算 | 每次调用 20 万条（可配），每 1024 条检查一次；超限只毁掉这一次调用 |
| 内存上限 | 每 VM 128 MiB（可配）；超限报"脚本内存超限"，不杀进程 |
| 能力 | 脚本默认只能读写世界 / 资产只读；文件、网络、系统时间、随机数需显式授权 |
| 随机 | `world.rng(stream)` 确定性流；禁止 `math.random` / `os.time` |
| 错误 | 指数退避限流；成功清零；不自动禁用脚本；错误带 `file:line:col` + 脚本栈 |
| 热重载 | 只清编译缓存；每实体状态按脚本 GUID + 实体保留；失败保留旧模块 |

### 8.4 API 生成与稳定性

- 脚本 API **由注册表生成**：每个 `Command` / `Query` / 引擎服务声明自动生成
  Lua 绑定、签名、清单、文档；不再手写 182 个函数 + 清单 + 文档表 + 计数断言。
- **名字是外部契约**：已有脚本里的 `spawn_entity` / `set_material` / `ui_clicked`
  等名字保留；内部实现替换。新 API 用一致命名（`entity.spawn` 还是 `spawn_entity`
  需拍板，默认保留旧名以保护用户资产）。
- **静态检查**：`script.check` 解析 Lua + 校验 API 存在性 / 参数类型 / 组件字段 /
  枚举值；错误定位到行列；AI 写完脚本先跑它，不用启动整个世界。
- **性能剖面**：`script.profile` 返回每模块 / 每函数 / 每 API 的耗时与调用次数。
- **测试**：`script.test` 跑 Lua 测试模块（headless、确定性时钟、断言世界状态）。

### 8.5 Rust 插件

- cdylib + 版本化描述符（`xgc_plugin_descriptor_v1`），只暴露 C ABI 与
  `repr(C)` 数据；注册组件 / 系统 / 导入器 / 渲染 pass。
- 受信任代码：不沙箱；版本不匹配拒载；句柄不卸载（继承当前"旧 DLL 永不卸载"的
  教训，避免卸载后函数指针悬垂）。
- 插件可以注册新组件——这正是"扩展靠注册"的体现；注册表在启动时合并。
- 插件热重载只支持"同版本、无状态迁移"；带状态迁移的插件热重载明确不做。

## 9. 资产管线

### 9.1 目录与形态

```text
project/
  project.xgc          # 项目配置（文本）
  scenes/*.scene.ron     # 场景（文本，可 diff）
  prefabs/*.prefab.ron   # 预制体（文本）
  scripts/*.lua
  shaders/*.wgsl
  assets/**              # 源资产（glb / png / wav / …）
  assets/**/*.meta       # GUID + 导入器 + 设置
  library/               # 烘焙产物（不入库，可重建）
```

| 形态 | 谁写 | 谁读 | 版本 |
|---|---|---|---|
| 源资产 | 人 / DCC / AI | 导入器 | 内容哈希 |
| `.meta` | 导入器 / 编辑器 | 资产库 | `meta_version` |
| 文本场景 / 预制体 | 编辑器 / AI / git | 运行时（经烘焙） | `format_version` |
| `library/` 烘焙 | 导入器 | 运行时 | `(source_hash, importer_version, settings_hash)` |

### 9.2 GUID 与 `.meta`

- GUID v7，导入时生成，**永不变**；移动 / 改名只搬文件与 `.meta`，不改引用。
- 磁盘存 `guid://…`，内存存项目相对路径；转换只在读写边界（继承当前纪律，
  但用生成的访问器保证没有第二个转换点）。
- `.meta` 缺失：`check` 报诊断，运行时用占位资产 + 错误；**不隐式补**（写检查
  必须只读）。
- 路径规则只有一处：`normalize_project_relative`（越界 / 盘符 / 冒号 / 结尾空格与点 /
  控制字符 / Windows 保留设备名）；读写两个边界都拒。

### 9.3 导入与烘焙

- `Importer` trait：输入源文件 + 设置，输出一组 `Artifact`；**纯函数**，同输入同输出。
- 并行：按资产独立，IO 线程池并发；依赖（材质 → 贴图）拓扑排序。
- 增量：内容哈希 + 导入器版本 + 设置哈希三者决定是否需要重烘；没变直接复用。
- 进度 / 取消：`asset.import` 返回任务 ID，可订阅进度、可取消；失败不留半成品。
- 烘焙产物：
  - mesh：顶点 / 索引 / 法线 / UV / 切线 / 包围盒 / LOD / meshlet；
  - texture：BC7 / BC5 / ASTC（按平台）+ mip；
  - audio：Opus / Vorbis；
  - anim：曲线 + 事件 + 根运动轨道；
  - shader：SPIR-V + 反射 schema + 变体表；
  - scene：二进制列式 + schema 哈希。
- **确定性**：同一源 + 同一设置 + 同一导入器版本 → 逐字节相同（时间戳不进入产物）。

### 9.4 依赖图与影响分析

```text
AssetId → { referenced_by: [EntityId | MaterialId | SceneId], depends_on: [AssetId] }
```

- `asset.dependencies` / `asset.references` / `asset.unused` 是 Agent 协议的一等查询。
- 删除资产前先查反向引用；被引用则拒绝并列出引用者（当前只能靠 `--check` 的
  悬空 GUID 事后发现）。
- `check` / 打包 / 运行时读路径共用同一张图，避免"检查说没事、运行时找不到"。

### 9.5 流式与内存预算

- `AssetServer`：引用计数句柄 + 优先级队列 + 预算；超预算按 LRU 淘汰（正在使用的
  不淘汰）。
- 大资产（贴图 / 音频 / 大 mesh）走 mmap + 分块上传；场景切换时预取下一关。
- 预算按类别（mesh / texture / audio / anim / scene），超预算产生诊断而不是 OOM。
- 加载失败：保留句柄 + 诊断 + 占位；不静默丢实体。

### 9.6 场景与预制体

- **场景**：实体列表 + 组件列 + 层级 + 环境 / 灯光 / 相机；文本格式稳定排序，
  `save→load→save` 第二轮逐字节不变。
- **场景切换**：是命令，帧边界应用；只重置"与实体绑定"的状态（物理 / 粒子 / 音频
  autoplay / UI 交互 / `started` / `state_*`），全局脚本变量与日志保留（继承决策记录
  §二十五）；装不上就不动 + 一条诊断。
- **预制体**：嵌套预制体 + 变体（Variant）+ **字段级 override**，从第一天就有。
  当前"整树 Revert、无字段级覆盖"是明确差距；新模型用 `(source_id, field_path)`
  表达覆盖，Revert 可以只还原一个字段。
- **实例化**：立即分配 ID（项目级），世界在屏障后可见；`Apply` / `Revert` 是命令，
  可预览 diff、可回滚。
- **迁移**：一次性 `xgc migrate` 把当前 `SceneV2` / `PrefabV2` 转成新格式；
  GUID 保留，实体 ID 按 §15.3 重映射；脚本 API 名保留；旧引擎冻结 tag 可回退。

### 9.7 存档

- **存档 = 状态覆盖层**：实体局部变换 + 刚体速度 + 全局 / 每实体变量；**不存**
  场景结构、生成物、时钟（继承当前 SaveGame 的语义）。
- **格式**：文本 RON（可 diff），带 `save_version`；按 `EntityId` 排序 ⇒ 同状态逐字节
  相同；写前体检（有限数 / 单位四元数 / 版本），不合法即拒。
- **读档**：替换不合并；对不上的实体跳过并计数；存档场景不同先切场景；实体查找
  一次建索引，不做 O(n²)。
- **与快照的区别**：快照是引擎内部全量（回放 / 调试）；存档是玩法层最小集
  （发布 / 玩家）。两者不共用格式。
- **迁移**：旧存档按 §15.3 的 ID 映射一次性迁移；版本不匹配拒绝，不自动双读。

### 9.8 构建与发布

- **流水线**：`xgc build` = 解析场景 → 烘焙资产 → 构建播放器 → 写 manifest
  （逐文件哈希）→ 自包含审计 → 原子发布。
- **自包含审计**：对包与源码工程各跑 `check` 取引用问题差集；包引入的新问题
  非空即失败（当前已经验证过的判据）。
- **原子发布**：长持文件锁 + staging + previous + 事务标记；无标记的同名目录绝不
  删除；下次构建先恢复（继承决策记录 §八十九 / §九十）。
- **可复现**：同一源码 + 工具链 + 资产 → 同 manifest 哈希；构建指纹记录引擎版本、
  插件 ABI、资产烘焙版本。
- **插件门禁**：版本 / ABI 不匹配拒载；插件清单位于唯一目录（继承 `Plugins/` 纪律）。
