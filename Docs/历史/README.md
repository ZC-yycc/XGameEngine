## 为什么保留

历史文档的价值不是“描述现在”，而是回答两类问题：

1. **当时为什么这样选？**（被否决的方案、量到的数据、踩过的坑）
2. **这个结论是什么时候、基于哪次提交得出的？**（审计快照、测试基线）

这两类问题无法靠读当前代码回答，所以归档而不是删除。维护现状时**不要改这里**；
发现历史结论与代码冲突，以代码和 `Docs/决策记录.md` 为准。

## 归档规则

见 [`Docs/文档规范.md`](../文档规范.md) §8。要点：

- 归档 = `git mv` 进本目录 + 顶部加“归档 / 冻结”横幅 + 更新所有相对链接。
- 归档文档**只修链接与错别字**，不再补写新结论。
- 同一主题如果已经有一份活跃文档，归档文档里必须写明“现状应看哪一份”，
  避免两份一起漂移。
