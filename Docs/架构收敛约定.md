# 架构收敛约定（反兼容层硬规则）

> 本约定的原话：
>
> **不要为了兼容旧框架而导致两种框架并行。以后做框架迁移或重构时，不需要兼容旧框架；
> 即使需要修改大量代码，为了保证整体框架优美和简洁，旧的设备直接拆除。**
>
> 一句话版本：**迁移 = 替换 + 拆除。旧设备直接拆掉，不搭临时通道。**

**体裁：规范 / 政策。** 本文只回答“遇到迁移该怎么做、什么算违规”，不记状态；
当前残骸用 `tools/check-no-compat.ps1` 看。

---

## 0. 效力与适用范围

- 适用于 `crates/`、`projects/`、`tools/`、`.github/` 的全部代码与数据文件。
- 与 `Docs/决策记录.md` 同级：冲突时选**类型更少、真相源更少**的那个方案。
- 这不是风格建议，是**合并门槛**：违反 §1 / §2 的 PR 不合并，没有"下个版本再删"。

---

## 1. 判据：什么算"兼容残骸"

判据只有一条：**同一个概念，仓库里是否同时存在两份可工作的实现？**
是 → 残骸。不管它叫"过渡层""适配器"还是"为了安全"。

| 形态 | 典型写法 | 为什么禁止 |
|---|---|---|
| 同概念双类型 | `Scene` + `SceneV2`、`Entity` + `EntityV2` | 每个字段都要写两遍投影，改一处必漏另一处 |
| 版本后缀 | `FooV2`、`_v2`、`FooNew`、`FooOld` | 文件名的版本号会变成永久地名；git 已经有版本了 |
| 长期转换桥 | `impl From<Old> for New`、`from_runtime` / `apply_to_runtime` | 桥一进主干就会被别处调用，删除成本随时间指数上涨 |
| 双份元数据 | `Inspect` + `Reflect` 两套字段表 | 两份表必然漂移，且新人不知道改哪份 |
| 双份判别枚举 | `RuntimeComponentKind` + `BuiltinComponent` | 新增一个组件要改 N 处，编译器不报错 |
| 双读双写 | 保存前先读回旧文件对位；新旧格式都写一遍 | 保存路径变长、错误类型分裂、只读文件系统下直接坏 |
| 弃用别名 | `#[deprecated]`、`pub use old as new` | 别名会活到下一个大版本；要么现在删，要么永远留 |
| 序列化兜底 | `#[serde(alias = "...")]`、给已改名/已删除的字段加 `#[serde(default)]` | 旧字段名从此成为契约，schema 与代码开始说不一致的话 |
| 死代码保留 | `#[allow(dead_code)]` + "以后可能用" | 编译器已经告诉你它没用了，别和编译器争 |
| 兼容目录 | `legacy/`、`compat/`、`shim.rs`、`adapter/` | 目录名就是"这里可以腐烂"的许可 |
| 镜像函数 | `load_runtime_scene` / `load_scene_runtime` | 两个名字一个语义，调用方靠猜 |
| 口头 TODO | "暂时保留""后续删除"但没有 issue 号与日期 | 没有到期日的债务等于永续债 |

### 不算残骸的三类东西（别误删）

1. **对外不可逆契约**：`guid://` 资产身份、实体 ID 的跨进程语义、MCP/CLI 的 JSON 字段名与退出码、脚本 API 的名字。它们被仓库外的文件或用户资产引用，改名 = 破坏用户数据。
2. **刻意的行为开关**：画质档位、`render.shadow.softness = 0` 这类"关掉走老路径"是**同一套代码的分支**，不是两套实现。判据仍是 §1：它有没有引入第二份同概念代码？
3. **真正的历史档案**：`Docs/历史/PLAN.md`、决策记录里的"当时为什么"。它们是文档，不参与编译。

**关键区分**：磁盘格式、插件 ABI、内部类型、编辑器状态模型、schema 生成方式——这些**允许一次性破坏**；一次性重写数据文件、涨版本号、旧插件拒载，都是正常操作，不是事故。

## 2. 标准动作（每个迁移 PR 必须按顺序做完）

1. **先定新模型**：一个概念一个类型，一个真相源。写不出"哪个类型是唯一真相"就还没设计完。
2. **改全部调用点**：编译器就是清单。`cargo check --workspace --all-targets` 必须清空，不接受"先留着旧路径让它编译过"。
3. **删旧实现**：类型、文件、模块、测试、文档一起删。不留 `pub use` 别名，不留 `#[deprecated]`，不留 `#[serde(alias)]`。
4. **一次性重写数据**：写个脚本跑一遍，提交结果，**脚本本身不入库**（或入库但在同一个 PR 内删除）。禁止运行时双读、双写、自动迁移。
5. **同 PR 更新派生契约**：schema、`--export-*` 清单、脚本 API 文档、编辑器布局校验。
6. **跑门禁**（§4）。
7. **PR 描述写两件事**：删除清单（文件/类型/函数名）、违规符号计数前后对比。

**完成判据是 `grep` 旧符号 = 0，不是"新路径能用"。**

## 3. 30 秒判断流程

```
旧实现还在被引用吗？
├─ 是 → 改完调用点，然后删掉它
└─ 否 → 现在删
需要迁移数据吗？
├─ 是 → 一次性脚本 + 版本号上调，脚本跑完即弃
└─ 否 → 什么都不做
需要旧插件 / 旧存档还能用吗？
├─ 是 → 先问"这是对外承诺还是内部惰性？"
│       ├─ 对外承诺（GUID/ID/JSON 字段名）→ 保留契约，改实现
│       └─ 内部惰性 → 拒绝加载，版本码挡住
└─ 否 → 直接破坏
需要 A/B 对比新旧实现吗？
└─ 用 git 分支或历史版本，不在主干留两套
```

## 4. 门禁

每个迁移 PR 至少跑：

```sh
cargo check --workspace --all-targets
cargo clippy --workspace --all-targets      # 0 警告
cargo test --workspace --all-targets
powershell -File tools/check-no-compat.ps1  # 报告残骸（默认不拦截）
```

- `tools/check-no-compat.ps1` 默认只报告；计数与 `tools/no-compat-baseline.txt` 对比，
  只打印增量，不拦人。
- `-Enforce` 把"超过基线"变成退出码 1 —— 这是收敛期的硬门禁：**基线只许降，不许升**。
- 删掉一批残骸后跑 `-WriteBaseline` 下调基线。手动改大基线等同新增兼容层。
- 复核命令：`powershell -File tools/check-no-compat.ps1 -Enforce`；CI 已按这个模式跑。
- 重构**不改变行为**时，额外跑字节/截图/无头基准（见 `AGENTS.md` 常用命令）。
- 行为确实要变时，在 PR 描述里逐条列出差异，并说明为什么不是回归。

## 5. 历史反例库（识别形态用，不代表当前状态）

这些形态在本仓库出现过（部分仍在收敛中）。写下来是为了让下一个人一眼认出来，而不是再讨论一遍。

| 反例 | 正确做法 |
|---|---|
| `Scene` / `SceneV2` / `RuntimeScene` 三件套 + 身份侧车 | 一个 `Scene`；磁盘形状由它自己的 serde 投影；身份内聚进实体 |
| `Inspect` / `Reflect` 两套字段表 | 只留 `Reflect::FieldMeta`；插件契约直接用 `Reflect` |
| `ComponentAddress` / `ComponentKey` / `RuntimeComponentKind` / `BuiltinComponent` 四份判别 | 一份注册表声明生成枚举与全部操作 |
| `xgame-math`：28 行 re-export 壳，9 个 crate 依赖 | 直接依赖 `glam` / `xgame_core`，删掉壳 crate |
| `load_runtime_scene` / `load_scene_runtime` 镜像名 | 一个 `load_scene`，删掉另一个 |
| 读返回 `Result<_, String>`、写返回 `ProjectError` | 读写同一错误类型，库层不出现 `String` 错误位 |
| 保存前先读回旧文件对位组件 ID | 身份常驻内存；保存是纯写 |
| 14 段组件面板只有 6 段走统一渲染 | 全部走 `Render::Fields`；缺的控件形态补到 `FieldMeta` |

> 收敛完成后，这一节只保留"形态 → 正确做法"，删掉具体类型名，避免文档变成过时的代码地图。

## 6. 给 AI Agent 的硬指令

1. **禁止**为了"不破坏现有代码"新增适配层、包装层、转换函数。
2. **禁止**保留未使用的字段/函数并加 `#[allow(dead_code)]`。
3. **禁止**用 `#[serde(alias)]`、`#[serde(default)]` 兼容旧字段名。
4. **禁止**写"新旧两条路径都支持"的代码，包括"临时"的。
5. **禁止**在注释里写"暂时保留"，除非同时给出 issue 号与删除日期（默认不允许）。
6. 遇到大面积编译错误：**继续改**，不许退回兼容层。错误数量不是保留旧实现的理由。
7. 不确定时选"删除 + 一次性重写"，而不是"先留着"。
8. 用户要求兼容旧格式时：先说明代价（两套实现、长期漂移、删除成本），再让用户确认；确认后也只做**边界契约**，不做内部双实现。
9. 判断"能不能删"只看引用与契约，不看"写了多久""删了可惜"。
10. 每次交付前跑 `tools/check-no-compat.ps1`，新增命中项必须在 PR 里解释或删除。

## 7. PR 自检清单

- [ ] 新模型是唯一真相源，写得出"哪个类型/函数是唯一入口"
- [ ] 全部调用点已改，`cargo check --workspace --all-targets` 干净
- [ ] 旧类型/文件/模块/测试/文档已删除（不是标记弃用）
- [ ] 没有 `V2` / `_v2` / `legacy` / `shim` / `compat` 新增
- [ ] 没有 `#[deprecated]`、`#[serde(alias)]`、`#[allow(dead_code)]` 新增
- [ ] 数据文件一次性重写完成，没有运行时双读/双写
- [ ] schema / 导出清单 / 文档同 PR 更新
- [ ] `tools/check-no-compat.ps1` 无新增命中（或已解释）
- [ ] PR 描述含删除清单与符号计数对比
