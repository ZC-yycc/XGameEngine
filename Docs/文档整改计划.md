# 文档整改计划

> **体裁：一次性计划。** 记录这次文档清理的现状判定、已执行动作、剩余阶段与完成判据；
> 完成后归档到 `Docs/历史/`，不长期留在活跃目录。
>
> 规则依据 [`文档规范.md`](文档规范.md)；文档总索引 [`README.md`](README.md)。
> 本计划不重新定义优先级；项目优先级只看 [`差距分析.md`](差距分析.md)。

---

## 1. 目标

把“体裁混用”的文档拆成**一类问题一份文档**，并让链接、归档、根目录白名单可自动检查。
不追求“文档更多”，追求：

- 打开任何一份活跃文档，第一屏知道它是现状还是历史；
- 想知道“还差什么”时，不需要在 1000 行关闭日志里翻；
- 移动 / 归档后不会留下断链；
- 新增文档不会又变成第二个真相源。

## 8. 风险与取舍

| 风险 | 取舍 |
|---|---|
| 移动 `PLAN.md` 会让旧书签 / 外部链接失效 | 内部文档，接受一次性断链；所有仓内链接同 PR 更新，历史索引保留入口 |
| 归档区旧链接可能指向已删除的代码路径 | 历史冻结，不追着代码修；脚本只报 warning，不阻塞 CI |
| 链接检查可能误报代码块里的示例 | 脚本跳过 fenced code block；误报按脚本 bug 修，不靠人工豁免 |
| 拆 `差距分析.md` 后“关闭记录”不再显眼 | 顶部开放表每条都指向归档记录；索引与 `Docs/README.md` 都有入口 |
| 规范本身又变成一份巨型文档 | 本文只写制度，不写状态；超过 1500 行按 §6 拆分 |
| CI 增加一步会拖慢反馈 | 纯文本扫描，秒级；放在 Checkout 后、编译前，失败得更早 |
